设计说明与待确认点

  1. ①「求和部分再做一份平均值」：求和类指标（金额 / 单量 / 访客数等）的「求和」块下方那行 日均 ¥X · N 天 就是额外补的平均值；下方「平均值」块内容与之相同（= 区间累计 ÷ 天数）。两处数值一致属正常——若觉得重复，可去掉独立「平均值」块，只保留求和块里的日均行。
  2. ② 比率类指标没有「求和」概念（转化率 / ROI / 客单价 / 推广占比 / 搜索点击率）。样例里把它们「求和」块改成展示分子与分母的区间累计，「平均值」块展示区间整体比率（先求和再相除，与现有后端口径一致）。另一种做法是比率类「求和」块直接写「不适用 / 不累计」。
  3. 待确认 A：比率类的「平均值」要不要改成「日均（每天比率求平均）」而非「区间整体」？两者数值略有差异，目前全站口径是「区间整体」，建议保持一致。
  4. 待确认 B：卡片变高（两块 + 间距）后，是否需要「默认只显示求和、点击/展开才显示平均值」的折叠交互？单日模式仍可维持现状的单值卡片。
  5. 待确认 C：是否要把「求和」和「平均值」拆成页面上两个独立分区（上排=求和指标区，下排=平均值指标区），而非每张卡内分两块？当前样例走的是「卡内两块」路线。
