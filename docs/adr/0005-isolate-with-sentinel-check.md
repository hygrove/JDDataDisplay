# 异常文件隔离，隔离必须附带哨兵验证

整理遇到形态异常、无法安全判定的文件（列不符、日期窗解析失败、跨月怪象）时，不猜规则、也不就地报错中断批处理，而是移出源表目录、放进**目录外**的隔离区，在报告里点名等人处理。猜规则的代价是静默污染数据，比不整理更糟；隔离区与归档区同样放在目录外，是为了不依赖"glob 非递归"这个会随时被改掉的隐式前提。

代价有两层，且都不会报错。长表 `daily_detail` 只增不减（`_upsert_long_table` 只有 `INSERT OR REPLACE`），移走一个含独有 key 的文件**不会让那些行消失**，而是把它们留在库里：从未入库过的 key 变成**历史缺口**，已入库的 key 则**停止更新、静默陈旧**——它还躺在聚合里，看起来有数据，其实再也不会变。项目里又已经有"白名单外的行被静默剔除、从不出声"的前科。所以隔离强制附带一道哨兵——把被隔离文件的数据 key 与保留集的 key 集合求差，只要存在某个 key 仅由该文件持有，就升级为 ERROR 级告警。这道哨兵是把"隔离了一份冗余文件"与"隔离了一份唯一数据源"区分开来的唯一手段；key 集合本来就是归档判据的副产品，边际成本近零。

## Consequences

哨兵只报警不阻断：批处理照常继续，数据缺口写进报告等人事后判断。这是有意的取舍——整理器无权替业务决定"这份数据能不能少"。隔离区不参与归档区的 60 天清理策略，那里的文件是在等人判断的，不是等清理的。
