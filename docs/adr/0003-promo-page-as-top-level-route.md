# ADR-0003 · 推广分析新建顶级页面 /promo，不并入模块页

- **状态**：已接受
- **日期**：2026-10-08

## 背景

现有信息架构：
- `/module/:moduleId` — 模块页，指标卡 + SPU 列表 + 明细表，按模块（pop / detail / promo）划分
- `/module/:moduleId/spu/:spu` — 单品分析页，时间序列 + 月份对比

推广预算分配是新增分析能力，需决定其页面归属。

## 决策

**新建顶级页面 `/promo`，与「模块」在左侧导航平级。**

页面含两种模式：
- **看板模式**（默认）— 随时查看当前各 SPU 推广效率状态
- **优化模式** — 点击「进入优化模式」展开深度功能：贪心分配方案、可优化空间、调整建议明细

## 理由

**不并入模块页**：模块页的指标卡与表格已占满纵向空间，无处安放四象限图；而预算分配的核心价值恰恰在于可视化。

**不并入模块页的第二个原因**：京准通预算是**店铺级**的，而模块页按数据模块（pop / detail / promo）划分，二者维度不一致，塞进去会造成割裂。

**不做成模块页内的 Tab**：四象限与下方全量表格语义不同（前者是决策视图，后者是数据浏览），Tab 切换只增加跳转成本，不降低认知成本。

**预算分配是独立的决策场景**，值得一个专属页面——它回答的是「钱该往哪投」，而现有页面回答的是「表现如何」。

## 后果

- 页面形态为「看板优先、优化按需展开」，与项目既有的「看数据」交互模式一致，不引入工作流式状态管理。
- 看板模式沿用现有工具条模式（日期区间 + 店铺选择 + 刷新），`DateRangePicker` 可直接复用。
- 日期区间语义统一为「最近 30 天滚动窗口，用于下一个预算周期」，并在页面显式提示大促期风险。
- 若未来需要跨店对比（各店规模差异极大，横轴不可直接比较），须另加设计，本期不做。

## 被否决的方案

- **并入模块页** — 无空间容纳可视化，且店铺级与模块级维度不一致。
- **做成模块页 Tab** — 增加跳转成本，语义不匹配。
- **决策工作流型（B）** — 推广操作的真实发生地是京准通后台而非本工具，要求用户在本页记录执行动作是「逆流」设计，会迅速荒废。故本期**只读、不记录执行历史**（见 ADR-0001 后果与 Q10 决策）。
