# 补货导出搬到后端，并把商品图嵌进工作簿

补货清单的导出要从"前端用 SheetJS 生成 xlsx"改成"后端生成 xlsx 并返回文件流"，因为需求要求导出里带商品图缩略图，而 **SheetJS 不能在 xlsx 里嵌入图片**。后端用 openpyxl 生成：一个工作簿两个 sheet——城市 sheet（分组头 + 身份列 + 每组小计 + 8 城总计）与 SKU sheet（明细长表，每行一个 SKU×城市，身份列逐行重复），有图的行把缩略图嵌进单元格区域，无图的行留空。导出与页面所见一致（同一套装配逻辑、同一组筛选与参数），ERP 编码缺失在导出里写 `0`。

## Considered Options

- **维持前端 SheetJS 导出**：改动最小，但嵌不了图，只能给一列图片路径文本——需求要的"导出带缩略图"落空；且导出数据由前端拼装，与后端口径存在漂移的余地。
- **前端导出 CSV**：同样嵌不了图；下游目前按 xlsx 对接，换格式是额外成本。
- **后端 openpyxl 生成并返回文件流（选定）**：能嵌图；导出与后端装配同源，所见即所得。代价是导出从一次前端调用变成一次后端请求（参数用 POST 传，返回文件流），前端的 xlsx 依赖退役。

## Consequences

前端的 xlsx（SheetJS）依赖不再需要，导出按钮改为请求后端并触发下载。缩略图取既有缩略图产物（按 SKU 组织、已被静态托管）读取，读不到的行留空、不报错——图片是展示层辅助产物，缺图不得阻断导出。导出工作簿里 ERP 编码缺失写 `0`（下游模板占位），页面同场景显示 `--`，两者语义不同且是有意的。

导出接口的参数（店铺、日期、搜索、视图、覆盖天数、安全系数、销速窗口）与清单查询共用，不能各写一份；否则"导出的表"和"看到的表"迟早对不上。
