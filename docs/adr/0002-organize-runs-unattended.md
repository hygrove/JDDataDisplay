# 整理在批处理中全自动执行，不设人工关卡

整理挂在批处理入口前自动执行。计划任务每天在无人值守时段跑批，"先出清单、等人确认再动手"这种人工关卡在日常运行里根本无法成立——等来的只会是整理从不执行。于是把偏好从"事前把关"改造成"事后可追溯"：每批整理必须留下清单与报告，任何一次归档都要能被复盘、被单独撤销。

## Consequences

没有人盯着，所以清单是唯一的事后追溯手段：清单缺失或损坏，那批归档等同于不可回滚。这也意味着整理失败**不应该**连带拖垮批处理——批处理侧本身有行级去重与唯一约束兜底，少归档几个文件只是浪费磁盘，不会污染指标。

容错粒度是**单个文件**：某个文件被占用、权限不足或解析失败时，跳过它、记进报告、继续跑完这一批。清单按"先写意图、再搬文件、搬完标完成"的顺序落盘（write-ahead）——反过来先搬后写，崩在半路就成了一笔糊涂账，再也说不清哪些文件动过；这个顺序看起来多此一举，但它正是崩溃后还能精确续做的唯一依据。

无人值守原则有**唯一一个例外**：首次上线。目录里此时积压着上百个文件、第一批就要搬走几十个，是整个设计里规模最大的一次不可逆动作——因此第一次先用 dry-run 跑出清单交给负责人过目，确认后同一份代码转入自动。例外只针对第一次，日常运行的全自动原则不变。
