# 不为归档重算开豁免，让门控机制自然感知

整理搬走文件会改变源文件集，`db.py` 的门控（`hashes == old`，`db.py:189-196`）因此判定为"变化"并触发一次整表重算。我们没有为它新造豁免机制（把归档登记为"非内容变化"）。

理由是实测出来的，不是省事：批处理每天都因新下载的文件触发一次整表重算，归档的额外重算**净增约零次**；整表重算实测 1.5 秒（门控本身 0.08 秒）；而代码里根本不存在 ignore 或豁免机制（`_collect_source_files` 只跳过 `~$` 锁文件），为它新造一套分档与豁免登记的复杂度，远超 1.5 秒的收益。

## Consequences

整理之后每次跑批都会有一次整表重算——这是**预期行为**，不是缺陷：重算正是让 `processed_file` 与整理后的文件集重新对齐的动作。

看到那多出来的一次重算，**不要去"优化"掉它**。豁免会让 `processed_file` 与磁盘实际文件集脱节，而这张表是判断是否需要重算的唯一依据；脱节的后果是"源文件变了但门控没察觉"，比多花 1.5 秒严重得多。缩略图不受影响（`pipeline.build_thumbs` 独立调用、走 mtime 幂等）。
