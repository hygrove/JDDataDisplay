# ADR-0011：库存缺口关注的双锚判定（覆盖率 + 估算缺货损失）

日期：2026-10-26　状态：已采纳
来源工单：`.scratch/restock-velocity-credibility/issues/02-gap-attention-flag.md`
前置：ADR-0010（可信销速三级估计器）

## 背景

运营诉求："一个周期内有货天数和周期天数相差很大，说明库存缺口很大，需要重点关注"——
但"相差很大"缺少可执行标准。单纯用覆盖率会误伤两类 SKU：

- **卖得慢又断货**（覆盖率极低但损失只有几件）——为 2 件损失折腾补货不划算；
- **卖得好但有货**（损失大但覆盖率够）——缺货期短，不算缺口。

## 决策

`backend/jobs/alert_rules.py` 新增纯函数 `stockout_gap`，返回 (关注档位, 估算缺货损失)：

```
coverage = 有货天数 ÷ 窗口天数            —— 缺口有多大
损失 L   = 日销速 × (窗口天数 − 有货天数)  —— 值不值得管

关注档位（先过损失门槛，再看覆盖率）：
  "关注"  coverage < 50%   （窗口里过半时间没货）
  ""      其余不关注
损失门槛 L_min = 5 件（2026-10-26 业务拍板；GAP_LOSS_MIN）
```

> 档位**只有一档**（2026-10-26 用户拍板）：原「断货 / 缺口」两档合并为一个「关注」，
> `GAP_SEVERE_COVERAGE`（30% 那档）随之删除。严重程度不再靠不同文案表达，
> 而是由说明句里的"缺货几天 / 损失几件"量化。**亮灯的行集合不变**（仍是
> coverage < 50% 且损失 ≥ 5 件），只是标签统一。

**损失率口径**：有货天数 > 0 用修正后销速；**有货天数 = 0 时改用 30 日参照销速**——
整窗缺货的损失不是 0，而是被完全截断的需求（这正是参照销速的用途）。这条与
"有货天数 = 0 → 不建议补货"策略不冲突：那条管"要不要建议补货"，这条管"损失多大"。

补货行新增 `gap_flag`（档位）与 `lost_sales`（估算损失件数）。前端在**状态列旁**
加紫色徽章（`关注`，与库存健康三档的红/琥珀/绿区分——那是水位，这是需求），
悬浮说明给出"缺货几天、损失几件"；导出两个 sheet 同步加「估算缺货损失」「关注」
两列。判定纯函数在 `frontend/src/modules/inventory.ts`
（`gapFlagMeta` / `gapFlagTitle`），`verify_inventory_display.mjs` 锁行为。

**导出如何承接"标记 + 悬停说明"**（2026-10-26，用户诉求："导出表格里也要有
断货/缺口标记和鼠标移入提示"）：
- 标记 → 「关注」列用页面同款紫色（字 #6d28d9 / 底 #f5f3ff）标出，不靠纯文本辨识；
- 悬停说明 → Excel 没有 HTML `title` 属性，用**单元格批注**（openpyxl `Comment`）承接，
  鼠标悬停即显示；批注文案与页面 title **逐字同口径**（`restock_export._gap_detail_text`
  ↔ 前端 `gapFlagTitle`），后端单测钉住这条文案，两边不许各写各的。

**导出表的列序与列语义**（2026-10-26 用户诉求："周期有货天数列并不知道周期是多少"、
"估算缺货损失列要更详细"、"预计可售天数列移到状态列前面"）：
- 「周期有货天数」→ 表头带周期：`周期有货天数（14日窗）`（数值本身只是"有货天数"，
  脱离周期看不出好坏）；
- 「估算缺货损失」→ 写**完整说明句**：`周期14 天仅 3 天有货（缺货 11 天），估算缺货损失 15.6 件`
  （亮灯行才写；不关注的行留空，不留"0 件"的噪音）；
- 「关注」→ 徽章列（紫色字 + 浅紫底 + 悬停批注）；
- 「预计可售天数」→ 移到「状态」之前（两 sheet 一致）。

## 为什么是这两个锚

- **覆盖率**回答"缺得久不久"——只看相对量，跨窗口可比；
- **缺货损失**回答"值不值得管"——把覆盖率翻译成件数（可再乘单价成金额），
  直接对接运营优先级；L_min = 5 件是业务拍板值（低于它不值得单独处理）；
- 两个锚是"与"关系：缺得久 **且** 损失大才亮灯，两类误伤各自被排除。

## 后果

- 实证（2026-10-26 快照，14 日窗）：1562 行中 45 行亮灯（2.9%），噪声可控；
  `100311879912` 北京行（有货 0 天）标「关注」、损失 69.1 件——
  按旧口径它因 L0（销速 0）永远不会亮，现在能被看见。
- 有意**不改变**既有排序（城市视图仍按建议补货量降序、SKU 视图按 SKU 升序）：
  排序口径是既有约定，本次只加可见标记；"按损失排序的重点清单"留作后续开关。
- 城市视图只显示建议量 > 0 的行，因此"整窗断货"（销速 0 → 建议量 0）的行主要出现在
  SKU 视图；城市级汇总（如每城亮灯 SKU 数）也留作后续。
- 参数化：`GAP_LOSS_MIN` / `GAP_COVERAGE` 集中在 `alert_rules.py`，调整不改调用方。
- ⚠️ 已知取舍：导出的「估算缺货损失」列现在是**说明句**（运营诉求：一眼看出缺了几天、
  损失几件），代价是该列**不能再按数值排序**（Excel 对文本按字典序排）；要看数值排序，
  可在同列里按句中的件数自行排序，或后续另加一列纯数字。
