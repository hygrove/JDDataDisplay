# ADR-0002 · 推广优化的理论上限必须标注线性假设限制

- **状态**：已接受
- **日期**：2026-10-08
- **相关**：[ADR-0001](./0001-greedy-budget-allocation-over-quadrants.md)、[CONTEXT.md](../../CONTEXT.md)

## 背景

贪心优化隐含一个硬假设：**给某 SPU 增加预算，其成交额按同比例线性放大**。

这个假设在高预算段几乎必然不成立——已投 ¥5000 的 SPU 边际流量已饱和，再加 ¥1000 不会带来对应比例的成交增长；而仅投 ¥50 的 SPU 加预算则可能成倍增长。

若页面直接显示贪心计算出的最优总成交，使用者会将其视为可达成的目标。实际执行达不到时，工具将失去可信度。

## 决策

**同时输出两个数字，且必须标注假设：**

1. **理论上限** — 贪心最优解，标注「线性假设下的数学最优，实际通常打折」
2. **保守估计** — 理论上限 × 回测折扣，标注折扣系数来源

**回测折扣**的算法：用历史区间回测——取某历史区间，假装不知其真实分配，按该区间的真实花费与投产比算贪心最优，再与该区间实际总成交相比，比值即折扣系数。

第一期数据不足（当前仅约一个完整月），该系数取**经验值 0.7**，并在页面标注为待替换。积累 ≥2–3 个完整区间后，改为由回测公式自动计算。**架构上预留为常量→函数的替换，实现不变。**

## 理由

数值可信度依赖来源可解释。人工设定的折扣系数（无论 0.6 还是 0.7）无法回答「凭什么是这个数」；而由该店历史数据回测得出的系数可以追溯到具体计算过程，即使不完美也是**这个店的真实历史命中率**。

## 后果

- 页面文案必须同时出现两个数字与两条说明，不可只显示其一。
- 「保守估计」与「理论上限」的差值本身就是不确定度提示，运营能直观看到假设的影响幅度。
- **大促期须人工介入**：工具无法感知「下月有双 11」，流量结构会变。页面须常驻提示「大促期请勿直接照搬本方案」。这一诚实性提示比算法精度更重要。

## 被否决的方案

- **仅显示理论上限（A）** — 只有一个不敢用的数字，用户无从判断实际能拿到多少。
- **仅显示折扣后预测（B）** — 单一数字会让使用者把保守估计误当作可达成的目标，掩盖了假设本身的不确定性。
- **人工设定的固定折扣系数** — 无法回答来源问题，长期失去信任。
