# 零贡献店铺的文件整组跳过，不参与整理

白名单里登记了 0 个 SPU 的店铺（当前是钻芯水饮电器旗舰店），其数据表每次批处理都会被整份丢弃。对这类店铺的文件，整理器**整组跳过、一个都不归档**，哪怕它们之间同样存在大量时间窗重叠、看起来极度冗余。原因是白名单会变：店铺随时可能被重新登记进来，而那一天若才想起去归档区翻找文件，代价远高于现在多读几个文件。

由此定下一条边界：**白名单只用于识别零贡献店铺，不参与归档判定本身**。让白名单影响归档，会把整理器焊死在白名单的当前取值上。

## Consequences

整理器需要读取白名单——这是执行本决策的必要条件，不是可选项。零贡献的判定必须在每批整理时动态重算，绝不能缓存成一次性结论，否则白名单一改，结论就成了陈旧的。
