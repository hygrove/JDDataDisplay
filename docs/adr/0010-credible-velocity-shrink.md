# ADR-0010：可信销速三级估计器（有货天数过少时收缩估算）

日期：2026-10-24　状态：已采纳
来源工单：`.scratch/restock-velocity-credibility/issues/01-credible-velocity-avail-column.md`
方案讨论：`.scratch/restock-velocity-credibility/方案-销速可信度与断货缺口.md`

## 背景

补货量公式 `qty = ceil(velocity × 覆盖天数 × (1+安全系数)) − 现货 − 在途`，其中
`velocity = 窗口出库 ÷ 窗口有货天数`。该口径对**有货天数充足**的 SKU 是对的
（把缺货期从分母剔掉，修正低估）；但当有货天数远小于窗口天数时反向爆炸：

- **分子污染**：唯一有货的那天往往紧跟着补货到仓，成交量里混入整个缺货期
  积压需求的集中释放（补货日爆发），不代表可持续日需求；
- **分母幸存者偏差**：只剩高动销日进了分母。

实证：SKU 100311879912 在 14 日窗内仅 1 天有货、出 66 件 → 直算 66 件/天 →
目标库存 ~713 件。真实销速夹在两个界之间：摊薄下界 66/14=4.7 ≤ v̂ ≤ 全速上界 66。

## 决策

`backend/jobs/alert_rules.py` 新增三级估计器 `credible_velocity`，替代
`effective_velocity`（已删除，`restock_qty` 改为传销速——销速只算一次，展示与
计算共用）：

```
L0  有货天数 ≤ 0      → 0（无销速依据，宁可不建议，不凭空估）——沿用原口径
L1  有货天数 ≥ 7      → 窗口出库 ÷ 窗口有货天数（样本覆盖完整周节奏）——沿用原口径
L2  0 < 有货天数 < 7  → 收缩估算（精算 credibility 思想）：
      v_ref    = 30 日窗出库 ÷ max(30 日窗有货天数, 15)      参照销速（分母垫底，
                 防参照窗自己也长期断货时踩同一个坑；参照无量退摊薄下界 out/30）
      v_short' = min(窗口出库÷有货天数, v_ref × 3)           突发封顶（积压爆发
                 最多按参照的 3 倍计；v_ref=0 时跳过封顶，退化为纯加权）
      w        = 有货天数 ÷ 7                                可信度权重（样本越少越信基准）
      v        = w·v_short' + (1−w)·v_ref
```

参数：`CRED_MIN_DAYS=7`（不足一个完整周的工作日/周末节奏）、`BURST_CAP=3`、
`REF_WINDOW=30`（参照窗固定 30 日；计算窗选 30 日时参照=自身，分母垫底后天然自洽）。

补货行新增 `avail`（窗口有货天数）与 `velocity_kind`（none/measured/shrunk）。
前端与导出把「缺口」列换成「周期有货天数」列（紧跟「日均销速」）；收缩行销速标
`≈`、有货天数琥珀色 + 悬浮说明。预警城市条的 restock_total 与清单同口径。

## 为什么不是别的方案

- **纯置信区间**：66 件/1 天在平稳泊松假设下相对标准误仅 ~12%，会给出"很精确的
  错误答案"——问题是**偏差**（积压释放破坏平稳性）不是方差，统计区间不适用。
- **分母垫底法**（`eff_days = max(avail, 窗口/2)`）：一行改动、好解释，但没有长窗
  信息修正（该 SKU 会算到 9.4 件/天 vs 收缩法 6.43 件/天）。保留为 v_ref 分母垫底
  与参照缺失时的退化路径。
- **日粒度剔除积压日**（用 `daily_detail` 识别补货首日）：最正确但要重构日粒度聚合，
  先上收缩法观察偏差，确有需要再做（Phase 2）。
- **零出库特判**（out=0 时强行给 0）：放弃。L2 是**对称**收缩——窗口仅 3 天有货且
  零出库的证据太弱，收缩后仍主要信 30 日参照（"近 30 天卖得好、本周刚回仓还没卖动
  → 该补"与"前半月清仓甩卖、后半月滞销 → 少补"在现有字段下无法区分，选统计一致的一侧）。

## 后果

- 正向：失真 SKU 回归正常量级（实证 100311879912：66 → 6.43 件/天，建议量
  ~713 → 30）；63/1590 行被标记收缩、有琥珀色提示，用户能看到销速的置信程度。
- 代价：零出库 + 有货天数 1-6 天的行可能因参照被拉起（上文对称收缩的取舍）；
  若实盘反馈误补，特判 `out ≤ 0 → L0` 即可（一行 + 一个测试用例）。
- 数据面：只读 `inventory_daily` 宽表的 `_out_30/_avail_30` 字段，**不触碰
  `daily_detail`**（ai-rules §1.1 铁律不受影响）。
