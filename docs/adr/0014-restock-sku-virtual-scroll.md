# 补货 SKU 视图上虚拟滚动 + 固定列宽

补货工作台的 SKU 视图（平铺长表）有 1500+ 行 × 12 列 ≈ 3.9 万个 DOM 节点，一次性构建要 ~1s（真浏览器实测 **1035ms**）。切视图时这段成本全额买单——ADR-0013 消掉了后端重算（228ms）之后，**渲染成了新的唯一瓶颈**。本次给 SKU 视图上虚拟滚动（只渲染可视区的十几行），并把表格改成固定列宽（虚拟滚动的必要配套）。

## 背景与动机

- **渲染是切换的最后一公里**：ADR-0013 之后，切到 SKU 视图 = 零网络请求 + 1035ms 渲染。实测 1562 行里 DOM 只渲染 18 行后，耗时降到 **100~255ms**。
- **虚拟滚动会抖列（必须一并解决）**：虚拟滚动只渲染可视区的十几行，若用 `table-layout: auto`，列宽由「这一小撮行的最宽内容」决定 → ERP 编码列在滚动中摆动 **52px**（138↔190px），其余列被它挤着一起晃（表格 `width:100%`，一列变宽别人就得让位）。用户读数字时列在横向跳，是比慢更难受的体验。
- **行高会变**：行高随字号缩放（`--font-scale` 是 CSS 变量）变化，写死常量会在用户调字号后错位。必须运行时实测。

## Considered Options

- **用 `@tanstack/vue-virtual`（项目已在用）**：库负责「滚动位置 → 可见行区间」的数学与测量。手写一遍容易漏边界——视口高度未就绪（首帧只渲染一行）、滚过头（tbody 空掉表格塌陷）、行高变化——每个都是「用户看到错行数据」级的坑。**选定**。
- **库的 div 网格模式（`GenericTable.vue` 的做法）**：行用 `position:absolute` + `translateY`。**不选**：补货清单是 `<table>`，要保住表头吸顶（`position:sticky`）、表尾合计行吸底、原生表格的列宽布局；绝对定位的行不在表格流里，列宽就失去依据了。改用**占位行方案**：库算区间，模板在 tbody 上下各插一个「高度撑开、内容为空」的占位 `<tr>`，表格结构原封不动。
- **手写一套窗口计算**：自己算「滚动位置 → 行下标」。**否决**：与库功能重复，项目里就会有两套虚拟滚动（§7 禁决策残留），且边界坑要自己踩。
- **分页替代虚拟滚动**：改动小，但把「一路滚到底看全部」的交互换成了翻页，且 1562 行翻 8 页体验更碎。
- **列宽方案**：
  - *保持 auto + 加宽列 ballast*：在表头塞隐藏的「最宽内容」撑住列宽。需为每列算出最宽内容（要测文本宽度），12 列各写一套模板 → 代码量大、漂移风险高。
  - *`table-layout: fixed` + em 列宽*：**选定**。列宽只由 em 值决定 → 不抖；em 跟着字号缩放走；两视图共用一套宽度。代价是内容超宽要截断，故给 ERP 编码加 `text-overflow: ellipsis` + `title` 悬浮看全码（不静默丢数据）。

## Consequences

- **切换耗时**：切到 SKU 视图 1035ms → **100~255ms**（虚拟滚动前 / 后，取决于浏览器缓存冷热）。切回城市视图 152ms（该表只有 129 行，本就不用虚拟滚动）。
- **DOM 规模**：SKU 视图 1562 行 → **18 行**（窗口 = 可视 11 行 + overscan 8，上下各留占位行撑出总滚动高度 107,850px）。
- **行高策略**：`utils/virtual-list.ts` 的 `pickRowHeight` 从窗口内各行取样、挑**众数**（不是最大值——偶发一条换行变高的行不该把整表行高撑大）。实测行高回填给库的 `estimateSize`，行高变了调 `measure()` 让它丢弃旧测量重新估算。字号缩放变化时自动重测（`useUiPrefsStore.scale` 响应式）。
- **固定列宽**：`.rp-table` 改 `table-layout: fixed`，各列宽用 `em`（相对表头字号 14px×缩放），总和 ≈1288px ≤ 容器 1300px（@1600 视口）→ 无横向滚动条。ERP 编码列 12em（最长码 23 字符 ≈159px 装得下；万一超长则截断 + 悬浮看全码）。
- **行高必须统一（虚拟滚动的前提）**：固定列宽后「商品信息」列的可用宽度 = 24em − 内边距 20 − 缩略图 48 − 间距 8 = 260px，正好等于身份行最长宽度 → 不换行 → 行高恒 69px（实测行高种类 `[69]`，全表一致）。这同时避免了「个别行变高 → 占位算错 → 行重叠」。
- **库的选择**：`@tanstack/vue-virtual` 已是项目依赖（`GenericTable.vue` 在用），本次复用，**没有引入新依赖**；项目里仍只有一套虚拟滚动实现。
- **新增验证**：`frontend/verify_virtual_list.mjs`（纯函数断言：行高众数策略、占位高度闭合不变量「上占位 + 窗口 + 下占位 = 总高度」），已接进 `npm run verify`。
- **验证方式**：真浏览器验收（`frontend/.scratch/restock-view-switch/verify_virtual_scroll.mjs`，项目内 `playwright` 驱动系统 Edge）**12 项全绿**，含：只渲染 18 行、总滚动高度撑满、表头吸顶 + 表尾吸底、无横向溢出、**滚动到 3 个位置行数据与后端真值对得上（偏差 ≤1 行）**、列宽不抖、滚到底 = 真值最后一行、行高统一、无内容裁切、切回城市视图 <300ms、控制台无报错。原有视图切换验收 13 项仍全绿。
- **遗留**：城市视图（129 行）未虚拟滚动——重建只要 152ms，不值得引入第二套装配逻辑。
