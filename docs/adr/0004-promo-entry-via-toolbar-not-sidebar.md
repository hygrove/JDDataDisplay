# ADR-0004 · /promo 不进侧边栏，从模块页工具条进入

- **状态**：已接受
- **日期**：2026-10-08
- **相关**：[ADR-0003](./0003-promo-page-as-top-level-route.md)

## 背景

ADR-0003 确定 `/promo` 为顶级路由，但未决定它如何出现在导航里。

调查发现（`backend/app/api.py:360` + `frontend/src/App.vue:102-115`）：
- `/api/manifest` 读取批处理产物 `manifest.json`，其中 `modules` 数组只含**数据模块**（各带`shops` / `date_range` / `spu_count`）
- 侧边栏由 `v-for="m in store.manifest?.modules"` 渲染，是**数据驱动**的
- `/promo` 是功能页面，无自有`shops` / `date_range` / `spu_count`（需跨店聚合得出）

## 决策

**不进侧边栏。** 在模块页工具条加入口链接指向 `/promo`。

## 理由

把功能页塞进数据驱动的导航有三条路，都有明确代价：

- **前端硬编码导航条目** — 破坏侧边栏「数据驱动」的一致性，后续每加一个工具页都要写死代码
- **改`manifest.json` 结构加 `tools` 数组** — 语义上更干净（manifest 从「数据模块清单」升级为「应用导航清单」），但需改动批处理输出与前端消费逻辑，范围蔓延到不该动的部分
- **仅加工具条链接** — 零结构性改动，功能完整可达

推广预算是「带着目的去用的工具」，不需要常驻侧边栏占位。

## 后果

- 入口可达性弱于常驻侧边栏：用户需先进入某模块页才能找到入口。若后续使用频率证明需要常驻，再评估改造`manifest` 结构（届时走 ADR 修订）。
- 该权衡的完整背景保留在本 ADR，日后若不理解为何 `/promo` 不在侧边栏，可回溯。

## 被否决的方案

- **前端 `App.vue` 硬编码导航项** — 与数据驱动导航不一致，且每加工具页都要改代码。
- **扩展 `manifest.json` 加 `tools` 数组** — 语义最佳但范围蔓延，超出本功能所需。
