# 异地克隆部署指南（JDDataDisplay）

> 适用场景：在另一台机器上 `git clone` 本项目后，从零把服务跑起来。
> 本文档的命令均已对照项目真实代码核实（`start_uvicorn.bat` / `package.json` / `run_batch.py` / `main.py` / `config.py`）。

---

## 0. 为什么不能直接跑——先懂原理

Git 仓库里**故意没存**四类东西，它们都是「机器相关 / 可重新生成」的：

| 被忽略的内容 | 位置 | 为什么忽略 |
|---|---|---|
| Python 虚拟环境 | `.venv/` | 含绝对路径，不可跨机器拷贝，靠 `requirements.txt` 重建 |
| 前端依赖 | `frontend/node_modules/` | 几百 MB，靠 `package-lock.json` 重装 |
| 前端构建产物 | `frontend/dist/` | 编译后的成品，由源码 `npm run build` 重新生成 |
| 运行时数据 | `backend/app/data/` | 由 `run_batch` 从数据源算出，是生成物 |

所以异地 clone 下来是个「半成品」，本地必须补齐这四样，服务才跑得起来。

> 好消息：`ResourceData/`（批处理的输入数据源）**默认是提交的**（`.gitignore` 里那行被注释掉了），所以 clone 下来就有数据来源，不用另外发文件。

---

## 1. 一次性前置环境（装在新机器上，不在项目里）

- **Git**：用来 clone。
- **Python 3.12+**：项目本地用 3.13，3.12 即可。python.org 下载。
- **Node.js 22+**：用来构建前端，`npm` 随它自带。nodejs.org 下载。
- （国内）pip 镜像：清华 / 阿里云都行；但 **Pillow≥12 的 AVIF 轮子清华偶尔缺**，装依赖卡在 Pillow 时换阿里云：
  ```
  -i https://mirrors.aliyun.com/pypi/simple/
  ```

---

## 2. 第 1 步：克隆

```bash
git clone https://github.com/hygrove/JDDataDisplay.git
cd JDDataDisplay
```

**原理**：clone 拉回来的是「源码 + 已提交的 `ResourceData/`」。`.venv` / `node_modules` / `dist` / `app/data` 都不在仓库里（见第 0 节）。

---

## 3. 第 2 步：后端 —— 建虚拟环境 + 装依赖

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

- `.venv` 建在**项目根目录**。`scripts/start_uvicorn.bat` 就是按 `%~dp0..` 推导根目录下的 `.venv`，所以项目改名 / 移动都不受影响。
- **原理**：`.venv/` 被忽略（虚拟环境不可跨机器拷贝），用已锁版本的 `backend/requirements.txt`（53 个包）重建即可。
- ⚠️ **别把别人的 `.venv` 拷过来用**，必炸。

---

## 4. 第 3 步：前端 —— 装依赖 + 构建（最容易漏）

```bash
cd frontend
npm install        # 从已提交的 package-lock.json 重建 node_modules
npm run build      # = vue-tsc -b && vite build，产出 frontend/dist
cd ..
```

- **原理**：`node_modules/` 和 `dist/` 都被忽略。`node_modules` 靠 lock 文件重装；`dist` 是浏览器真正跑的**编译后成品**，服务器托管的是它，不是 `.vue` 源码。
- ⚠️ **致命坑**：不 build，`main.py` 检测到 `frontend/dist` 不存在就不挂载 SPA 路由 —— 结果 `localhost:8000` 打开空白 / 404，只有 `/docs` 接口能用。
- 纯前端开发可免 build，用 `npm run dev`（5173 端口，代理 `/api` 与 `/images` 到 8000）；但「把服务整体启动起来」必须 build。

---

## 5. 第 4 步：生成运行时数据 —— `run_batch`

```bash
python -m backend.jobs.run_batch
```

- **原理**：读 `ResourceData/`（已提交），算出各模块指标 JSON + SPU 原图 + 缩略图，写进 `backend/app/data/`（该目录被忽略，因为是生成物）。
- ⚠️ **第二个致命坑**：不跑这步，服务器能起，但**所有数据接口都是空的**——页面骨架在、数据全无。`main.py` 把 `/images`、`/thumbs` 都挂在这个 `app/data` 上，没它前端图片也裂。

---

## 6. 第 5 步：启动服务

```bash
# 方式 A（Windows，自动推导根目录、检查 .venv）：
scripts\start_uvicorn.bat

# 方式 B（通用，项目根目录执行）：
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

- **原理**：单端口 **8000** 同时托管四样 —— `/docs`(API 文档)、`/images`、`/thumbs`(运行数据)、以及 `dist` 里的网页（仅当 dist 存在时挂 SPA 回退）。CORS 预留了 5173 给 vite dev。
- ⚠️ **坑**：8000 被旧 uvicorn 占了会 bind 失败。先 `netstat -ano | findstr :8000` 拿 PID，`Stop-Process -Id <PID>` 杀掉再起。

---

## 7.（可选）计划任务自动更新

`scripts/install_tasks.bat` 注册「每日 03:00 刷新 + 开机自启 uvicorn」（需管理员）。**不是启动必需**，只是让你数据常新。异地机器一般先手动跑通再考虑。

---

## 8. 依赖顺序（谁等谁）

```
clone（含 ResourceData）
   ├─ 后端：venv + pip install        ┐
   ├─ 前端：npm install + build       ├─ 三者互不依赖，可并行
   └─ run_batch（需 后端依赖 + ResourceData）→ 产出 app/data
                                          ↓
                              启动服务（需 dist ✅ + app/data ✅ + .venv ✅）
```

最短路径：**装后端依赖 → build 前端 → run_batch → 启动**。前两步独立，最后两步有先后。

---

## 9. 异地特例排坑

- **若你以后把 `ResourceData/` 也忽略了**：clone 就不会带数据，得手动把 `ResourceData/` 拷到项目根再 `run_batch`。当前默认是提交的，正常不用管。
- **config.yml 是空 `{}`、无需 .env**：所有配置都有环境变量默认值，`PG_DSN` 留空 = 跳过数据库源。所以新机器**零配置文件要写**，开箱即跑。

---

## 10. 验证成功没

1. 打开 `http://localhost:8000` → 看到数据看板；
2. 打开 `http://localhost:8000/docs` → API 文档在；
3. 看 `backend/app/data/status.json` 里 `"success": true`。

三处都对，就说明这条异地链路通了。
