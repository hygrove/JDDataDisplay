# A 类 · 数据口径（错了是数据事故）

## R-01 ★★★ 比率类指标必须「先求和再相除」

### 为什么错

比率**不可加**。但很多代码会不自觉地把它当可加字段处理——最常见的两种错法：

**错法 A**：在明细行先算好比率，汇总时再求和或取平均。

```
某商品 8/1~8/31，每天转化率：5%, 50%, 5%, 50% ...
简单平均 = 27.5%   ← 完全错误
```

**错法 B**：对比率做加权平均，但权重选错。

### 正确写法

**分子分母各自求和，再相除**：

```
真实转化率 = Σ成交客户数 / Σ商品访客数
```

举例：两日分别 5/100=5%、50/10=50%，汇总 = 55/110 = **50%**，不是 27.5%。

### 落地位置

**后端**：`aggregate()` 先 sum 分子分母，`compute_metrics()` 再相除。

```python
def aggregate(df, keys):
    # 只累加可累加指标，比率不在 agg 之列
    out = df.group_by(keys).agg(
        pl.col("visitors").sum(), pl.col("buyers").sum(), ...
    )
    return compute_metrics(out)     # ← 比率在这里算，口径天然复用
```

**前端**：结构必须与后端**对称**——

```ts
function sumRawMetrics(points) { /* 累加：所有 sum 指标 ∪ 所有 ratio 的分子/分母 */ }
function aggregateMetrics(points) {
  const sums = sumRawMetrics(points);
  for (const m of METRICS) {
    if (m.agg.kind === "ratio") {
      out[m.key] = sums[m.agg.den] ? sums[m.agg.num] / sums[m.agg.den] : null;
    } else out[m.key] = sums[m.key] ?? null;
  }
}
```

### 验收

**必须有一条断言**：造2 天数据（转化率 5% 和 50%），断言汇总值 = 总客户数/总访客数，
**且断言它不等于 27.5%**。这条不过，后面全白搭。

## R-02 ★★★ 分母为 0 返回 null，绝不返回 Infinity / NaN

### 为什么错

```python
df.with_columns((pl.col("a") / pl.col("b")).alias("rate"))   # b=0 时得到 inf
```

后果链条：`inf` → JSON 序列化成 `null` 或 `Infinity` → 前端显示混乱 → **ECharts 遇到非法值可能整图崩掉**。

### 正确写法

```python
def safe_div(a, b):
    return pl.when(b.is_not_null() & (b != 0)).then(a / b).otherwise(None)
```

⚠️ **两个陷阱**：

1. **`NaN != 0` 为 True**，所以只判 `b != 0` 不够，必须同时判 `is_not_null()`。
2. 前端也要同样处理：`den ? num / den : null`，不要写 `num / den` 了事。

### 展示约定

`null` / `NaN` / `undefined` **一律显示 `--`**，不显示 `0`——
「没数据」和「真的是 0」是两件事。

## R-03 ★★★ 比率类指标绝不入长表

### 为什么错

一旦比率进了长表：

- 存进去的是**当日比率**，不是可累加的值；
- 任何一层再聚合都会出错，且**没有任何提示**。

### 正确写法

```
长表只存：shop, date, spu, spu_name, category
        + visitors, buyers, orders, items, amount,
          search_impressions, search_clicks,
          promotion_cost, promotion_amount,
          refund_orders, refund_amount
```

⚠️ **源表里可能有「成交转化率」「客单价」等同名列**——
**不要映射进长表**，在列名映射表里显式注明「源表虽有同名列，但汇总时不能直接相加/取平均」。

这也是 A-02 记录的判断依据：**新数据源接入时，若发现长表含比率，说明设计已被破坏**。

## R-04 ★★★ 区间累加的字段集合 = 所有 sum 指标 ∪ 所有 ratio 的分子/分母

### 为什么错（本项目最隐蔽的 bug）

假设某个字段`search_clicks` 是 `search_click_rate` 的分子，
但**它本身不在指标清单里**（不作为独立指标展示，只用来算比率）。

那么写累加时如果只遍历指标清单：

```ts
for (const m of METRICS) sums[m.key] += ...      // ❌ search_clicks 永远不会被累加
```

结果：`search_clicks` 的和恒为 0 → **搜索点击率永远显示 0.00%**。

**这就是本项目历史上「单品分析页搜索点击率一直 0.00%」的根因。**

### 正确写法

```ts
const sumKeys = new Set<MetricKey>();
for (const m of METRICS) {
  if (m.agg.kind === "sum") sumKeys.add(m.key);
  else { sumKeys.add(m.agg.num); sumKeys.add(m.agg.den); }   // ← 关键
}
// 然后遍历 sumKeys 累加
```

### 附带约定

- 累加时 `null`（当日缺失）与 `NaN`（脏数据）**都要跳过**，不污染结果。
- **另暴露一个独立函数**给「需要展示分子/分母明细」的场景用——
  `aggregateMetrics()` 的返回值只含指标清单里的 key，读隐藏分子会恒为 `undefined`（显示 0）。

## R-05 ★★★ 「百分点 pt」按**单位 `format`** 判定，不按算法 `agg.kind」

### 为什么错

这是最反直觉的一条。看这个表：

| 指标 | 聚合算法 | **单位** | 差额该怎么写** |
| --- | --- | --- | --- |
| 成交转化率 | ratio | `percent` | **百分点**：`1.92% → 1.56%` = `−0.35pt` |
| **客单价** | **ratio** | **`currency`** | **金额**：`¥489.32 → ¥510.90` = **`+¥21.58`** |
| 商品访客数 | sum | `number` | 数值：`−1,067` |
| ROI | ratio | `decimal` | 数值：`−0.38` |

**客单价是 ratio 聚合，但它的单位是金额。**
如果按 `agg.kind === "ratio"` 就判定为「百分比」，会得出：

```
客单价 489.32 → 510.90，算成「+2158.00pt」   ← 荒谬
```

### 正确写法

**判据是展示格式（单位）**：

```ts
// ✅ 字段名用 isPercent（不是 isRatio）——ratio ≠ 百分比
const pt = spec.format === "percent";
```

字段命名也必须体现这个区别：叫 `isPercent` 而不是 `isRatio`，
否则下一个人会继续犯同样的错。

### 真实数据示例（用于自测）

某商品 8 月 vs 9 月：

| 指标 | 8 月 | 9 月 | 差额 | 变化 |
| --- | --- | --- | --- | --- |
| 客单价 | ¥489.32 | ¥510.90 | `+¥21.58` | `+4.4%` |
| 成交转化率 | 1.92% | 1.56% | `−0.35pt` | `−18.5%` |
| ROI | 3.35 | 2.97 | `−0.38` | `−11.3%` |
| 推广占比 | 19.39% | 15.69% | `−3.70pt` | `−19.1%` |

## R-06 ★★★ 同一份数据只允许一个 computed 作为事实来源

### 为什么错

真实事故：**勾选「同天数对比」后，表格数据已按 30 天截取，但表头仍显示 31 天。**

根因是两个来源：

```ts
const daysMap = computed(() => {   // ❌ 用了 rawRanges（原始区间）
  out[mo] = dayCountInRange(rawRanges[mo]);
});
const rangeMap = computed(() => {  // ✅ 用了对齐后的区间
  ...
});
```

取数用`rangeMap`，表头用 `daysMap`——一个对齐了、一个没对齐，必然出现矛盾。

### 正确写法

**「展示什么」和「取什么数」必须来自同一个 computed。**

```
rawRanges  →  rangeMap（对齐后的区间）  →  { 范围用 }
                                       ├→  { 天数用 }      ← 都从 rangeMap 派生
                                       └→  { 取数用 }
```

### 通用原则

任何时候出现「A 处显示 X，B 处计算 Y，两者应该一致」的需求，
就要检查它们**是否来自同一个来源**。这是前端口径事故的最主要来源。

## R-07 ★★★ 对齐取最小值收敛，绝不反向延长

### 为什么错

场景：两个自然月数据天数不同（8月 31 天 vs 9 月 30 天），
需要对齐到相同天数才能公平比较。

**错误实现**：只拿 A 与 B 比天数，**只截 A**。

```
A 在左边且 A 天数更多（31 vs 30）
→ 截断点（A+30 天）越过 A 自身的 end（A 本身只有 31 天，但目标 30 天在范围内）
→ 代码走进「不反向延长」分支原样返回
→ 表现为「完全没截」
```

这是一个**方向性 bug**：只有当较短月在左边时才截，**较短月在右边就完全失效**。

### 正确写法

**所有选中项都对齐到全局最短天数**，与左右顺序无关：

```ts
const target = Math.min(...days);          // 全局最短
// 每个区间独立收敛：target = min(target, 自身天数)
// 绝不为某个区间「反向延长」到target
```

**「绝不反向延长」比「截断」更重要**——反向延长会造出不存在的数据。

### 扩展到任意数量

两两比较会漏。多个区间时应取**全局最小值**：
「所有月对齐全局最短天数」，而不是「相邻两两对齐」。

### 配套提示

- 天数不等且未对齐时，**必须给出提示条**（如「所选月份天数不同，涨跌可能受天数影响」）。
- 对齐后改显「已按 N 天对齐：各月均只取前 N 天数据」。
- 某月某指标无数据时显示 `—`，**不编造差额**。

# B 类 · 前端正确性（错了功能不成立）

## R-08 ★★★ 缩进只作用于文字，底色与分割线必须铺满整个容器

### 为什么错

直觉写法：给表格外层加 `padding-left` 来做缩进。

```
❌ .mc-body { padding-left: 48px; }
```

后果：整个表格画布**右移**，而底色与分割线只画到内缩处→ **两侧露白**。
用户看到的正是「斑马纹和分割线突然断掉、没延伸到白色背景边缘」，
或者「在黄色提示下面套了一个框」「表格被塞进了另一个容器」。

### 正确写法

```
✅ 外层横向 padding 归零
✅ 缩进由「各行自身」的 padding-left 提供
```

```css
.mcompare { --mc-inset: 48px; }
.mc-body{ padding: 0 0 16px 0; }                    /* 横向归零 */
.mc-rowline{ padding: 7px 18px 7px var(--mc-inset); } /* 各行自己缩进 */
```

### ⚠️ 一个易混的坑

**表格内的悬停红条**用 `box-shadow` 而不是 `border-left`：
整行 padding 含缩进变量，加border 会让标题**横向位移 1px**，与下方表格对不齐。

### 验收方法

此类布局改动后**固定实测两个数字**：

1. 表格画布左右边界 vs 外框内容区（应**相等**，空隙 0/0）；
2. 指标文字到画布左缘距离（应**等于**缩进变量）。

## R-09 ★★★ 内联 SVG 必须 1:1 渲染

### 为什么错

```
❌ <svg viewBox="0 0 620 200" style="width:100%">
```

SVG 规定：`viewBox` 定义内部坐标系，`width/height` 定义显示尺寸。
**两者不等时浏览器按比例缩放**。

真实事故：`viewBox` 写死620，容器实际 1227px → 浏览器横向拉伸 `scaleX = 1.979`（近 2 倍），
内容显得巨大违和。

**⚠️ 此时调小字号只是治标**——你缩的是被放大后的值。
真实做法是让 `viewBox` 宽 == CSS 像素宽。

### 正确写法

```ts
const boxW = ref(620);
let ro: ResizeObserver | null = null;
onMounted(() => {
  ro = new ResizeObserver(() => { boxW.value = el.clientWidth; });
  if (el) ro.observe(el);
});
onBeforeUnmount(() => ro?.disconnect());      // ← 必须解绑

const W = /* 动态计算，见下 */;
```

### ⚠️ 宽度不应恒等于容器宽

全宽时，2~3 个数据点的连线会**横穿整屏**、气泡孤立居中。

正确做法是**按数据点数反推**：

```
W = PAD_X*2 + (n-1)*SEG        （SEG=段间距132, PAD_X=左右留白62, MIN_W=460）
W = max(MIN_W, min(needW, max(容器上限, MIN_W)))   ←夹在容器上限内
```

实测：2~3 点→460，4→520，5→652，6→784，8→1048；超出则压缩 + 横向滚动。

### 配套：靠左不居中

SVG 用 `:width="W"` + `display:block`，**不要 `margin: 0 auto`**——
居中会在两侧留白，看起来像「图形被套进另一个框」。

## R-10 ★★★ `v-for` 内的 DOM 引用必须用函数式 ref

### 为什么错

```html
<div v-for="row in rows" ref="box">   <!-- ❌ -->
```

Vue 对`v-for` 内的**字符串 ref 会收集成数组**（`ref[]`）。
于是 `box.value` 是 `HTMLElement[]`，`box.value.clientWidth` 是 `undefined`：

```ts
boxW.value = box.value.clientWidth;      // undefined
// → viewBox 退回默认值 → 「我改了没效果！」
```

### 正确写法

```html
<div v-for="row in rows" :ref="setBox">  <!-- ✅ -->
```

```ts
// ⚠️ 必须标注 VNodeRef 类型，否则 vue-tsc 报 TS2322（签名需要第二个参数）
const setBox: VNodeRef = (el) => {
  if (el) ro.observe(el as HTMLElement);
};
```

### ⚠️ 函数式 ref 的解绑陷阱

Vue 在patch 时会依次传 `null` 和新元素。

**错误做法**：解绑时清空整个集合。

```ts
const setBox: VNodeRef = (el) => {
  if (el) boxes.add(el);
  else boxes.clear();       // ❌ 多行场景下会把其它元素踢出观察范围
};
```

**正确做法**：解绑的 `null` **什么都不做**——
解绑元素 `clientWidth` 为 0，取最大值时自然忽略；真正清理由 `onBeforeUnmount` 兜底。

### 配套：多容器场景

若容器可能有多个（多行同时展开），观察集合要累积全部、**宽度取最大可用值**：

```ts
const boxes = new Set<HTMLElement>();
function apply() {
  let best = 0;
  for (const b of boxes) best = Math.max(best, b.clientWidth);
  if (best > 0) boxW.value = best;
}
```

**否则只有最后绑定的那个被观察**——先展开的行在窗口缩放时不会更新尺寸。

## R-11 ★★★ SVG `marker` / `clipPath` 的 `id` 文档级唯一

### 为什么错

```html
<marker id="arrow">...</marker>    <!-- ❌ 多行都用这个 id -->
```

**SVG `id` 是文档级唯一的，不受组件作用域隔离。**
多行共用同名 id 时，后出现的会覆盖先出现的 → **部分行的箭头直接消失**。

### 这个 bug 的恶劣之处

- **不报错**
- **构建通过**
- **类型检查通过**
- **只有真正看到页面才发现**

### 正确写法

```html
<marker :id="`arrow-${row.key}`" :marker-end="`url(#arrow-${row.key})`" />
```

**凡是在 `v-for` 里渲染带 `id` 的 SVG 元素（marker / clipPath / mask / linearGradient），
`id` 一律按行加后缀。** 这类问题排查极难，从一开始就要写对。

## R-12 ★★★ CSS 覆盖规则必须带父级前缀提高特异性

### 为什么错

真实事故：**绿涨红跌「看起来没生效」。**

```css
/* 基础规则 */
.mc-table td { color: #333; }        /* 特异性：0,2,1 */

/* 覆盖规则 */
.up { color: green; }                /* 特异性：0,1,0 → 被压住！ */
```

代码写了、类名没错，但**颜色不生效**。而且**用肉眼看模板看不出来**。

### 正确写法

```css
.mc-table td.up{ color: var(--color-up); }     /* 特异性：0,3,1 → 生效 */
.mc-table td.down { color: var(--color-down); }
```

### ⚠️ 所有覆盖类都要检查

同一类问题在多个地方出现（单元格、时间轴 SVG 的 `fill`、气泡背景）：
凡是「给某个元素改颜色/样式」的类选择器，
**都要确认它的特异性高于基础规则**。改完必须实测计算样式（见 `03-验收清单.md`）。

# C 类 · 工程纪律（错了诡异难查）

## R-13 ★★★ 日期一律用本地时间 Date + 手动补零，禁用 toISOString()

### 为什么错

```ts
❌ d.toISOString().slice(0, 10)
```

`toISOString()` 返回 **UTC** 时间。在东八区（UTC+8），本地 `2026-10-01 00:30`
会被转成 UTC 的 `2026-09-30 16:30` → **日期差一天**。

表现：「10 月 1 日的数据算到了 9 月 30 日」，且**只在东八区凌晨出现**，极难复现。

### 正确写法

```ts
const pad = (n: number) => String(n).padStart(2, "0");
const y = d.getFullYear(), m = d.getMonth() + 1, day = d.getDate();
const key = `${y}-${pad(m)}-${pad(day)}`;        // ✅ 本地时间 + 手动补零
```

**配套**：日期是定长 `YYYY-MM-DD` 字符串，**字典序即时间序**，
可以直接用字符串比较做区间判断，不需要 `Date` 解析（更快也更少出错）。

## R-14 ★★★「精确某年某月」不能用 offset 换算

### 为什么错

```ts
❌ monthBounds(offset)   // offset 是「相对系统当前月」
```

月份选择器支持**翻年**（`‹ 2026 年 ›`）。用户翻到 2025 年再翻回去，
若用 offset 换算：`offset = (2025 - 2026) * 12 + (8 - 10) = -14`，
**跨年时极易算错**（负数进位、月数溢出 0~11 之外）。

### 正确写法

**提供两个函数，分工明确**：

```ts
monthBoundsOf(year, month0, min?, max?)// ✅ 精确某年某月：直接传绝对年月
monthBounds(offset, min?, max?)         // ⚠️ 仅用于「当月/上月」快捷键
```

月份选择器**只用 `monthBoundsOf`**。相对偏移函数只服务于「当月 / 上月」这类按钮。

### 配套：月份清单由数据反推

**不写死「近 N 个月」**：

- 数据只有 2 个月 → 写死会出现一堆点不动的空月份；
- 数据跨 2 年 → 写死又让早期月份直接选不到。

正确做法：以数据 `min`/`max` 为上下界**逐月枚举**，超出范围的年份置灰。
枚举时**用「绝对月序号」（`年*12 + 月`）做倒序遍历**，避免逐年分支处理跨年。
⚠️ 加**上限兜底**（如 240 个月 = 20 年），防止传入异常值时死循环。

## R-15 ★★★ SPA 的 `index.html` 必须 no-store

### 为什么错

Vite 构建产物分两类：

| 文件 | 文件名 | 能否长缓存 |
| --- | --- | --- |
| `/assets/*.js` `*.css` | **带内容 hash**（内容变则文件名变） | ✅ 可以长缓存 |
| `/index.html` | **文件名固定** | ❌ **必须 no-store** |

`index.html` 是「指向当前该用哪个 hash 资源」的**入口**。
一旦被浏览器缓存：改完前端重新 build，用户刷新仍拿到**旧 `index.html`** →
继续加载**旧 hash 的 JS/CSS**。

### 症状：极难自查的「改了没生效」

```
源码是新的✓   dist 是新的 ✓   页面完全没变化 ✗
```

**每一步单独看都是对的**，这就是它难查的原因。

### 正确写法

```python
NO_STORE_HEADERS = {
    "Cache-Control": "no-store, no-cache, must-revalidate",
    "Pragma": "no-cache",
}
# 回退到 index.html 时带上
return FileResponse(FRONTEND_DIST / "index.html", headers=NO_STORE_HEADERS)
```

⚠️ **这个修复需要重启服务才生效**——必须写进文档，否则下次排查会白忙一场。

## R-16 ★★★ `前端 agg` 不得重做后端已算的派生动作

### 为什么错

后端逐行算好的派生值（如 `净收益 = 成交−花费`），前端再写一遍减法。

### 真实后果

两边各算一次→ 必然漂移。且后进改了口径（如改成扣毛利），
前端会**静默留在旧口径**——页面看起来完全正常。

### 正确做法

前端 `agg` 只能填 `{{ kind: "sum" }}`。
可以直接累加的依据是**加法对减法封闭**：`Σ(aᵢ−cᵢ) ≡ Σaᵢ − Σcᵢ`。

## R-18 ★★ 单串形式的多文案强制要求无法被断言

### 为什么错

要求“三处免责文案缺一不可”，但把它们拼成一段字符串。
断言只能检查“整体包含某个词”——
**删掉第 2 条时，第 1、3 条的关键词仍能 grep 到，断言照样绿**。

### 正确做法

1. 结构化成数组（`disclaimers: list[str]`）——“恰好 3 条”本身就可断言；
2. 每条各含一个**互不相同**的关键词（否则删掉一条时另一条还能匹配）；
3. 前端再做一道展示层兜底，失败时**页面显式报警**。

⚠️ 同理适用于任何“必须共现的多项”的交交地式（字段、步骤、条件分支）。

## R-19 ★★★ 前端改动必须真浏览器实测，build 通过不等于生效

### 真实案例：scoped 选择器不跨组件

父组件样式表里写 `@media reduce { .chip { transition: none } }`
，对子组件元素**完全无效**—— Vue scoped 会加数据-属性选择器，
父组件选不中子组件的 DOM。

实测证据：同一屏 `.rate-fill`（父组件自己的）reduce 下已关掉，
`.chip`（子组件的）仍是 `0.15s`。**`npm run build` 零错误**。

### 分类

| grep dist 能证明 | 不能证明 |
| --- | --- |
| 代码被打包进 dist | 浏览器里真的生效 |
| 新字符串在 | 嵏柏导致结果不一致 |
| 样式规则写进了 | scoped 选择器选中了对的元素 |

# 附录 D · 补充纪律（不属于 A/B/C 三类，但同样重要）

## D-01 缺失一律显示 `--`，绝不显示 `0`

`null`（没数据）和 `0`（真的是 0）是两件事。
混淆会导致「无数据的商品看起来像销量为 0」。

## D-02 累加时跳过 `null` 与 `NaN`

```ts
if (typeof v === "number" && !Number.isNaN(v)) sums[k] += v;   // ✅
// ❌ 直接 += ：null 会把结果变成 null（JS 中 null + 5 = 5，但 null + null = 0，行为不可预期）
```

## D-03 颜色只按数值方向，不做业务判断

**绿涨红跌**（国内习惯），但**不做业务好坏判断**：
推广花费下降业务上是好事，仍标红。读者需要的是「数值方向」，不是「业务评价」。

⚠️ **语义色要一次抽对**：
「涨」的绿与「操作成功」的绿**不是同一个色**（后者偏青绿）。
同屏出现两种绿会像两套语义。抽token 时定义 `--color-up` / `--color-down`。

## D-04 同一 SPU 多行的名称取「最新非空值」

```ts
if (row.spu_name) spu.spu_name = row.spu_name;   // ✅ 只在非空时覆盖
// ❌ 直接赋值：后出现的空值会把前面已得到的名称覆盖成None
```

## D-05 图表汇总必须排序

`aggregate(df, ["shop","date"]).sort(["shop","date"])`
不排序时折线会**来回跳**。

## D-06 时间序列画线的两个细节

- 连线**在到达下一节点前约 10px 处停止**，箭头落在两节点间隙里**不被节点遮住**。
- **节点圆点必须画在连线之上**（SVG 按文档顺序绘制，后写的在上）。

## D-07 浮层互斥用模块级 ref + 实例唯一 id

同页多个浮层需要「全局只允许一个展开」。
**刻意不用 `provide/inject`**——同一个组件实例内可能有多个浮层（见日期选择器同时有日历+月份面板），
需要它们共用一个 id，此时 `provide/inject` 无法做到。

## D-08 空态插画只加在「无数据」分支

**不要放在「加载中」分支**——加载态会误显示空态插画。

## D-09 格式化「整数值」的函数不要用来格式化平均值

`fmtNumber()` 会 `Math.round`。用它格式化日均值（15÷22=0.68）会显示成 **1**。
平均值走单独函数，最多保留两位小数。

## D-10 Windows 编码坑

- `.ps1` / `.bat` / `.vbs` 内容**必须纯 ASCII**（PS 5.1 / cmd 按 GBK 读 UTF-8，中文注释会吞行导致解析失败）。
- `.py` / `.pyw` 无此坑。
- PowerShell 5.1 **不要用 `*>` 重定向**（会写 UTF-16）；用 `Out-File -Encoding utf8` 或 `[IO.File]::WriteAllText(..., UTF8)`。
- 子进程输出编码：按字节捕获后 `decode(errors='ignore')`，不要假设控制台编码。
