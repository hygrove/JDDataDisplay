> 配套 `00-主提示词.md` 第六阶段。核心命题：
>
> **「跑通了」不是验收标准，「可重复执行的判据」才是。**
>
> ⚠️ 本文件里的方法都来自真实教训。每条 ⚠️ 都对应一次「看起来做完了、其实没生效」的事故。

## 零、验收哲学

| 级别 | 说法 | 是否算数 |
| --- | --- | --- |
| ❌ | 「代码写完了」 | 不算 |
| ❌ | 「能跑了」 | 不算 |
| ❌ | 「在构建产物里 grep 到新字符串了」 | **不算**——只能证明构建通过 |
|✅ | 有一条断言，它现在失败、改对了才通过 | **算** |
| ✅ | 在真实浏览器里读到了计算样式 | **算** |
| ✅ | 在另一台机器上按文档跑通了 | **算** |

## 一、回归断言脚本（必做，成本最低收益最高）

### 1.1 为什么要自动化断言

口径错误的特征是**「看起来正常」**——比率算错了，页面照样显示一个数字，
不写断言根本发现不了。而这些错误往往是「想当然」引入的，修完还会再犯。

### 1.2 技术方案

**不引入额外运行时**（不装 tsx / vitest / jest）。做法：

```json
{
  "scripts": {
    "verify": "npm run verify:logic && npm run verify:api",
    "verify:logic": "esbuild verify_xxx.mjs --bundle --platform=node --format=esm --outfile=node_modules/.cache/verify_logic.mjs --log-level=warning && node node_modules/.cache/verify_logic.mjs",
    "verify:api": "esbuild verify_agg.mjs --bundle --platform=node --format=esm --outfile=node_modules/.cache/verify_agg.mjs --log-level=warning && node node_modules/.cache/verify_agg.mjs"
  }
}
```

- 用 `esbuild` 就地把 `.ts` 转译后由 node 执行，产物落 `node_modules/.cache/`（已 gitignore）。
- 入口分两个：**纯逻辑**（无前置条件）与 **真实接口**（需服务已启动）。

### 1.3 必须断言的场景

#### A 类 · 数据口径（**一条不过就不能继续**）

```js
// ① 比率：先求和再相除（★最重要）
//    造2 天：5/100 和 50/10
assert(round4(agg([{buyers:5,visitors:100},{buyers:50,visitors:10}]).conversion_rate) === 0.5,
       '汇总转化率必须是 总客户数/总访客数=55/110=0.5，不能是 (5%+50%)/2=27.5%');

// ② 分母为 0 → null，不是 Infinity
assert(agg([{buyers:0,visitors:0}]).conversion_rate === null, '分母0必须给null');

// ③ 隐藏分子参与累加（R-04）
//    search_clicks 不在指标清单里，但搜索点击率必须算对
const r = agg([{search_clicks:10,search_impressions:1000}]);
assert(round4(r.search_click_rate) === 0.01, '隐藏分子必须参与累加，否则点击率恒为0');

// ④ 缺失值跳过累加，不污染结果
//    [10, null, 20] 应得30，不是 30 也不是 NaN

// ⑤ null 与 0 的区分
//    缺失日 → null；有效但为 0 → 0
```

```python
# ⑥ 后端同样要断言（批处理层）
#    同一份数据，后端产出的汇总转化率必须与前端一致
#⚠️ 前后端各写一份聚合实现，必须有断言证明两者一致，否则两边漂移没人知道
```

#### B 类 · 日期逻辑

```js
// ⑦ 天数计算：闰年 / 跨月 / 单日
assert(days('2026-02') === 28); assert(days('2024-02') === 29);   // 闰年
assert(days('2026-08') === 31); assert(days('2026-09') === 30);
assert(days('2026-09-17', '2026-09-17') === 1);                   // 单日

// ⑧ 绝对月序号倒推：跨年不偏
assert(months('2025-11-20','2026-02-03').map(m=>m.key)
       .join(',') === '2026-02,2026-01,2025-12,2025-11');

// ⑨ 同天数对齐：方向性（R-07）
//    8月31天 vs 9月30天 → 两者都取前30天，与左右顺序无关
assert(trim(8月区间, 30).end === '2026-08-30');
assert(trim(9月区间, 30).end === '2026-09-30');

// ⑩ 绝不反向延长（★反向验证）
//    30天 vs 31天，目标是30天；此时若实现反向延长会把9月拉到31天
assert(trim(9月区间, 30).end !== '2026-10-01', '绝不能反向延长造出不存在的数据');

// ⑪ 月份排序恒为时间升序，与用户勾选顺序无关
assert(picked(['2026-09','2026-07','2026-08']) === ['2026-07','2026-08','2026-09']);
```

#### C 类 · 单位判定（R-05）

```js
// ⑫ 百分点 vs 金额：按 format 判定，不按 agg.kind
assert(diffLabel('conversion_rate', 0.0192, 0.0156) === '−0.35pt');  // percent
assert(diffLabel('avg_price', 489.32, 510.90) === '+¥21.58');          // currency（但 agg 是 ratio！）
assert(diffLabel('roi', 3.35, 2.97) === '−0.38');                    // decimal
assert(diffLabel('visitors', 1067, 1000) === '−67');// number

// ⑬ 相对变化率：分母 0 → '--'
assert(delta(0, 5) === '--');       // 不能是 Infinity
assert(round2(delta(100, 80)) === -0.2);   // (80-100)/|100|
```

### 1.4 ⚠️ 断言失败时先怀疑测试本身

**这是本项目最反直觉的经验：历史上多次 FAIL，根因都是期望值写错，不是代码错。**

常见三类：

| 症状 | 真实原因 | 正解 |
| --- | --- | --- |
| 浮点差一点点 | 期望值写的是未舍入的精确值 | 期望是舍入结果时，**容差按舍入粒度给**（如 `0.005`），不是 `1e-9` |
| 符号反了 | 逻辑写反（新−旧 vs 旧−新） | 先用具体数字手算一遍，再写期望 |
| 数量级离谱 | 记了百分点给金额 | 先确认单位（就是 R-05） |

**所以**：写断言时**先手算一个具体数字**，再写进期望值。
不要「看着代码推期望」。

### 1.5 Go/No-Go

```bash
cd frontend && npm run verify
```
✅ 全部断言通过。**A 类断言一条不过就停下**，不要继续往下做。

## 二、真实浏览器实测（UI 改动交付前必做）

### 2.1 为什么不能用 grep 替代

```
grep 新字符串 dist/assets/*.js  →  ✅ 证明「构建通过」
                                        ❌ 不证明「浏览器里生效」
```

「构建通过」和「页面生效」之间隔着：CSS 被覆盖、viewport 不对、动画还没播完、
浏览器缓存了旧文件、测试样本选错了……**这些都不会让构建失败。**

### 2.2 标准流程

```bash
# 1)启动 headless 浏览器并开调试端口（用系统浏览器，不要另装 Chromium）
<browser> --headless=new --remote-debugging-port=9333 \
         --user-data-dir=<项目内临时目录> --no-first-run --disable-gpu --no-sandbox about:blank

# 2) 用 node 内置 WebSocket 直连调试协议（node 22+ 全局 WebSocket，无需装包）
#    PUT /json/new?url=<目标页>  →  得到 target
#    Page.enable → Runtime.evaluate → Page.reload
```

⚠️ **浏览器必须 `run_in_background` 启动**，不能同步等它退出。

### 2.3 ⚠️ 六个必须知道的坑

#### 坑 1：headless 默认视口很小

默认约 500×450，直接量元素会因**换行**得到荒谬值（实测头部量到 219×107）。

```js
Emulation.setDeviceMetricsOverride({width: 1500, height: 950, deviceScaleFactor: 1, mobile: false});
Page.reload();     // ⚠️ 必须 reload，否则布局不重算
```

#### 坑 2：测动画必须抓过程值，不能只看终态

一次性动效在「固定等若干秒再读样式」时**必然测到 `animationName: none`**（因为已播完撤类），
会得出「动画没生效」的假结论。

**正解**：挂载瞬间**连读多次**（约 150ms 间隔读 8 次），看数值是否变化：

```js
for (let i = 0; i < 8; i++) {
  const v = await evalStyle();       // 例：读translate 的计算值
  samples.push(v);
  await sleep(150);
}
assert(samples.some(v => v !== samples[0]), '动画期间必须有中间值');
```

#### 坑 3：测 hover 必须用真实鼠标事件

```js
// ❌ 不会触发 CSS :hover 匹配
element.dispatchEvent(new MouseEvent('mouseover'));
// ✅ 真实鼠标移动
Input.dispatchMouseEvent({type:'mouseMoved', x, y});
```

#### 坑 4：测 hover 必须挑「未展开/未激活」的行

已展开的行本来就是目标色（比如三角本来就是红的），
测它会得出「hover 前后一样 → hover 没效果」的**假结论**。

**正解**：用代码**动态找未激活的样本**：

```js
const idx = rows.findIndex(r => !r.classList.contains('expanded'));
```

#### 坑 5：截图传 `clip` 可能返回空

```
Page.captureScreenshot({clip: {...box, scale:2}})   // ⚠️ 可能返回无 data
```
→ 改用**整页截图**，人工核对。

#### 坑 6：Vue 的 `:key` 不是 DOM 属性

```js
document.querySelector('[key*="mt"]')   // ❌ 永远选不到
```
→ 按**几何特征**筛（`getBoundingClientRect` 位置/尺寸），或用 `data-testid`。

#### 坑 7：点击前不往 scrollIntoView，事件被**静默丢弃**

```js
Input.dispatchMouseEvent({x: rect.x, y: 979})   // 视口高度只有 950
```
原因：`getBoundingClientRect` 给的是**视口坐标**，不是页面坐标。
元素在视口外时事件丢弃、**无报错、无 console 输出** —— 表现为“点了没反应”，很像功能坏了。
→ 点击前先 `el.scrollIntoView({block: 'center'})`，`sleep(350)`，**再**取坐标。

#### 坑 8：选择器选中了表头而不是数据行

```js
document.querySelectorAll('.c-spu')[0]   // 表头！不会触发行点击
```
表头行里也有同名类（复用列定义）。
→ 加 `data-testid` 区分：`[data-testid="table-row"] .c-spu`。

#### 坑 9：只改 CSS 媒体查询模拟不了 reduce

```js
matchMedia('(prefers-reduced-motion: reduce)')   // 永远 false，即使你写了该媒体查询
```
→用 CDP：`Emulation.setEmulatedMedia` + `{features:[{name:'prefers-reduced-motion', value:'reduce'}]}`，
然后读 `getComputedStyle` 的 `transitionProperty` / `animationName`。

#### 坑 10：取测定宽列时容器本身被撑开

写了 `min-width: 1160`（= 各列宽之和），实测却是 `1181`。
原因：flex item 的 `min-width` 默认 `auto`（= min-content），长文案撑开它。
→ 给每个定宽列 `min-width: 0`，再重测。
同例：别用 `:nth-child` 定列宽（依赖“每行列数完全相同”这个隐藏前提），用显式类名。

### 2.4 必测项清单

| 测什么 | 怎么测 | 判据 |
| --- | --- | --- |
| **缩进方向（R-08）** | 量表格画布左右边界 vs 外框内容区 | **相等**（空隙 0/0） |
| |量指标文字到画布左缘距离 | **等于**缩进变量 |
| **SVG 1:1（R-09）** | 比 `svg.getBBox().width` 与 `getBoundingClientRect().width` | 比值≈1.0（实测曾达 1.979） |
| **CSS 生效（R-12）** | `getComputedStyle` 读颜色 | 变色了才算 |
| **id 唯一（R-11）** | 遍历所有 `marker` 的 `id` | 无重复 |
| **hover 变红** | 挑未激活行，真实鼠标移入，读 `fill` | 灰 → 品牌红 |
| **动画（R-）** | 抓过程值 | 有中间值 |
| **多行同时展开** | 点多个行，量各容器 `viewBox` 与 `marker id` | 各行几何独立、id 不重复 |
| **浮层互斥** | 打开一个浮层，再点另一个 | 前者自动关闭 |
| **定宽列被撑开** | 量表格 `min-width` 与各列宽之和 | 严格相等（实测曾为 1181 vs 应为 1160） |
| **子组件动效被 reduce 关掉吗** | CDP `Emulation.setEmulatedMedia` 模拟 reduce，读 `.chip`（子）与 `.rate-fill`（父）的 `transitionProperty` | 两者都 `none`（只关父组件的 = 子组件漏掉） |
| **无限循环是否停了** | reduce 下读 `animationName` | `none`（旋转器对前廊敏感用户是真问题） |
| **强制要求文案齐全吗** | 数组长度 + 每条关键词命中 | 恰好 N 条且每条 `ok=true` |
| **带 `v-if` 的入口真的存在吗** | 刷新后查 DOM | 不在则排模块条件 / `?bare=1` 诊断参数 |

### 2.5 「看起来没变化」先分类

⚠️ **两种完全不同的情况，别混淆**：

| 情况 | 判据 | 处理 |
| --- | --- | --- |
| ① 真没生效 | 计算样式 == 原值 | 查CSS 是否落地 / 是否被覆盖 / 是否缓存 |
| ② **生效了但幅度不可见** | 计算样式已变，但视觉差异小 | **别改代码**，是设计问题（如 33px vs 477px） |

**把 ② 当成 ① 重调，是 wastes 时间的经典错误。** 先读计算样式。

### 2.6 头号真凶：浏览器缓存 index.html

若出现「源码对/ dist 新/ 页面旧」的矛盾，**先让使用者强制刷新（Ctrl+F5）**。

⚠️ 后端加 `no-store` 的修复**需要重启服务**才生效——
若没重启就测试，会误判「修复无效」。

### 2.7 ⚠️ 服务启停权归使用者

AI 不主动启停用户的服务。需要临时验证时可启动，但**必须在当轮结束前停掉**。

## 三、口径一致性交叉校验

### 3.1 前后端口径必须一致

前后端各有一份聚合实现（后端给API 用，前端给区间实时聚合用）。
**必须有断言证明两者一致**，否则两边会漂移。

做法：用同一份真实数据，
分别取后端接口的区间汇总与前端 `aggregateMetrics` 的结果，逐字段比对。

### 3.2 导出表vs 页面

导出是独立实现（行列结构完全不同），最容易出现「页面和导出对不上」。
必须验证：**同一筛选条件下，导出的总计 == 页面显示的总计**。

### 3.3 三个层级必须一致（R-01 的实际含义）

对同一批数据，四层聚合应满足：

```
单日值  ⊂店铺汇总 ⊂ 日期汇总 ⊂ 区间汇总     （概念上的包含关系）
且每个比率层 = 该层分子和 / 该层分母和
```

**特别测**：比率类指标在四层下的值，
**不应等于「各层比率的算术平均」**。

## 四、构建与配置检查

### 4.1 必跑

```bash
cd frontend && npm run build     # vue-tsc + vite，必须 0 error
cd frontend && npm run verify    # 全部断言
```

### 4.2 ⚠️ 「改了没生效」的归因树

前端改动**只需重新 build + 刷新浏览器**；后端改动或重跑批处理**必须重启服务**。

这两条看似矛盾，实际是：

| 改动 | 生效方式 | 原因 |
| --- | --- | --- |
| `.vue` / `.ts` / `.css` | 重新 build → 刷新 | 静态目录实时读磁盘 |
| 后端 `.py` | **重启服务** | 旧进程内存里是旧代码 |
| 批处理 / 数据源 | 重跑批处理 **+ 重启服务** | 旧进程缓存了旧 JSON |

**遇到「改了没生效」，按这张表从下往上查，不要瞎改代码。**

### 4.3 配置自检

- [ ] 所有配置项都有默认值 → **零配置开箱即跑**
- [ ] 没有任何绝对路径被烧进脚本 / 计划任务 / 镜像
- [ ] `.gitignore` 覆盖：虚拟环境 / `node_modules` / `dist` / `*.db` /运行时数据 /
      真实业务数据 / 日志 / 编辑器配置 / `.env` / `_` 前缀临时产物
- [ ] 样例数据已入库，且有脚本把它铺到真实数据目录
- [ ] 数据库文件不入 git（删了可从源文件全量重建）

### 4.4 ⚠️ 文档一致性检查（**最容易被忽略**）

**文档会漂移。** 必须逐条核对：

- [ ] 文档里的**每条命令都实际可执行过**
- [ ] 「哪些文件不入 git」的清单**与 `.gitignore` 逐条对应**
- [ ] 「改什么需要 build / 需要重启」与实际实现一致
- [ ] 文档描述的默认端口、路径、模块 id 与代码一致

> **真实案例**：部署指南写「`ResourceData/` 默认是提交的，clone 下来就有数据」，
> 但 `.gitignore` 早已排除该目录，`git ls-files` 返回 **0**。
> 文档与现实脱节，照文档操作会直接卡住。
>
> **对策**：每次改配置就同步文档；关键事实**用命令核实而不是凭记忆写**。

## 六、给agent 的提醒

⚠️ **不要在没跑完验收前宣布完成。**

具体地说，以下话术**不构成完成**：

- ❌「已实现，你看看对不对」——没跑断言、没在浏览器看过
- ❌「代码已写完，构建通过」——只说了构建
- ✅「断言全过（列出数量），浏览器实测：XX 值从 A 变成 B，截图已核对」

⚠️ **发现问题先怀疑自己的代码，其次怀疑测试**——
但注意：**历史多次断言 FAIL 确实是测试本身写错**（期望值算错）。
两边都要查，别预设「测试肯定对」。

⚠️ **不确定的地方要问，不要猜**：
- 指标口径的**业务**正确性（该用哪个分子分母）→ 问使用者
- 数据的**边界**情况（跨年、闰月、残缺月）→ 写断言覆盖，别自己假设
- 视觉偏好（字号、配色深浅）→ 属人工迭代范围，别声称一次到位
