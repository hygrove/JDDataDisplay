## 二、任务目标

把散落在多张 Excel / CSV 里的**多店铺商品经营数据**，整合清洗后以**可交互的可视化页面**呈现，

1. **模块列表页**：按店铺 / SPU 展示指标，支持日期区间筛选、指标勾选、搜索、排序、导出。

## 四、技术栈（硬约束，不得擅自替换）

### 4.1 后端

| 层 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |
| 数据处理 | Python + **Polars** | polars≥1.44 | 清洗/聚合。不用 pandas、不用 SQL 引擎 |
| 数据建模 | **Pydantic v2** | pydantic≥2.13 | 所有输出结构必须有模型 |
| 持久化 | **原生 `sqlite3`** | 标准库 | **零新依赖**，单文件嵌入式库 |
| 接口 | **FastAPI** | fastapi≥0.141 | |
| 服务 | **Uvicorn** | uvicorn≥0.53 | 单端口同时托管 API + 页面 + 图片 |
| 表格读取 | **openpyxl** | openpyxl≥3.1 | 只读映射表时延迟导入 |
| 缩略图 | **Pillow** + pillow-avif-plugin | Pillow≥12 | AVIF + WebP 双格式 |

**为什么 SQLite 而不是 PostgreSQL / Docker**：
单机内网工具，运营要「双击就能用」。零外部依赖 = 零部署成本。
但**必须预留数据库源接口**（`db_source.py`留骨架），迁移路径见 `04-迁移手册.md`。

**⚠️ 为什么Polars 而不是 pandas**：
Polars 表达式 API（`pl.col("x").sum().over("y")`）让聚合口径集中在一处，
比 pandas 的逐行 `apply` 更不容易写出口径漂移。

- **不引入 UI 组件库**（不装 Element Plus / Naive UI）。全部手写 `<style scoped>`。

## 五、⚠️ 十五条铁律（**全文最不可违背的部分**）

**这十五条每一条都对应一个真实事故**。完整解释与正反对照见 `02-口径铁律.md` 与 `05-反例清单.md`。

| # | 铁律 | 一句话理由 |
| --- | --- | --- |
| R-01 | 比率类指标**先对分子分母各自求和，再相除** | 否则「单日对、汇总错」 |
| R-02 | 分母为 0 时返回 `null`，**绝不返回 Infinity / NaN** | Infinity 序列化后前端显示异常甚至崩图 |
| R-03 | 比率类指标**不入长表**，由聚合层统一计算 | 明细行算好再求和 = 口径错 |
| R-04 | 区间累加的字段集合 = **所有 sum 指标 ∪ 所有 ratio 的分子/分母** | 只遍历指标清单会让「隐藏分子」恒为 0 |
| R-05 | 「百分点pt」按**单位 `format`** 判定，**不按算法 `agg.kind`** | 客单价是 ratio 聚合但单位是金额，按算法会得出 `+2158.00pt` |
| R-06 | 同一份数据**只允许一个 computed 作为事实来源** | 否则出现「数据已按 30 天截取、表头写 31 天」 |
| R-07 | 跨月/跨区间对齐取**最小值**收敛，**绝不反向延长** | 「不反向延长」比「截断」更重要 |
| R-08 | 缩进**只作用于文字**，底色与分割线必须铺满整个容器 | 加在表格外层会让画布右移、两侧露白 |
| R-09 | 内联 SVG **必须 1:1 渲染**（`ResizeObserver` 动态 `viewBox`） | 写死 viewBox 会被浏览器拉伸（实测 1.98倍） |
| R-10 | `v-for` 内的 DOM 引用**必须用函数式 ref** | 字符串 ref 会聚成数组，`clientWidth` 变 undefined |
| R-11 | SVG `marker`/`clipPath` 的 `id` **文档级唯一**（按行加后缀） | 多行共用 id 会互相覆盖、箭头消失且不报错 |
| R-12 | CSS 覆盖规则**必须带父级前缀**提高特异性 | `.up` 被 `td{color}` 压住，「代码写了颜色没生效」 |
| R-13 | 日期一律用**本地时间 `Date` + 手动补零**拼字符串 | `toISOString()` 转UTC，东八区差一天 |
| R-14 | 「精确某年某月」**不能用 offset 换算** | 跨年时offset 极易算错 |
| R-15 | SPA的 `index.html` **必须 no-store** | 缓存导致「代码改了、dist 更新了、页面没变」 |

> **这十五条会在「阶段 3」和「阶段 6」各复述一次**。这是刻意的冗余，
> 用于对抗长提示词中后段约束被稀释的问题。请勿在复述时删减。

### 阶段 1 · 数据源层（Source 协议 + 清洗）

**做什么**：定义统一长表列清单与数据源协议，实现清洗逻辑。

**必须支持的清洗步骤**（顺序有讲究）：
1. 扫描源文件（**固定子目录**，不遍历「最新日期文件夹」——换一天就换目录极不稳定）。
2. 跳过 Excel 打开时产生的 `~$*.xlsx` 锁文件（读它会抛 `CalamineError`）。
3. 从文件名解析店铺名（约定 `{店铺名}_商品明细_{日期}.xlsx`）。
4. 列名映射：源表中文列名 → 统一英文列名，**只保留映射表里登记过的列**。
5. **去重**：多份明细表日期区间会重叠，按业务唯一键（如 `店铺+日期+SPU`）保留最后一次出现。
6. **关联补充数据**（如推广数据 CSV）按业务键左连接；连接前先丢弃同名列。
7. **白名单过滤**：只保留登记表中登记过的条目。
   ⚠️ **明细与补充数据必须做完全一致的白名单过滤**，否则连接后会出现单边数据。
8. **名称映射**：用简化名表覆盖原名，映射表没有则保留原名。
   ⚠️ 映射表/登记表都是**可选增强**，任何异常都不应中断批处理。
9. 补齐缺失列，统一列顺序，返回列集合严格等于长表列清单的DataFrame。

**Go/No-Go**：
- 重复跑两次结果完全一致（幂等）。
- 白名单为空时行为明确（是「不过滤」还是「全过滤」），并在注释里说明。
- 补充数据某月缺失时能正常产出（该月补充字段为 null）。

### 阶段 2 · 持久层与聚合层（**口径的地基，最重要**）

**做什么**：建立数据库表 + 增量摄入 + 聚合口径实现。

#### 2.1 持久层

**必须包含两张表**：
- **明细长表**：只存**可累加的原始指标**，业务唯一键上加 UNIQUE 约束，用 `INSERT OR REPLACE` 保证幂等。
- **源文件追踪表**：记录每个源文件的相对路径 + 内容哈希 + 处理时间。

**⚠️ 增量策略——用「文件集级别」而非「逐文件级别」**：
1. 收集全部源文件并计算 sha256；
2. 与追踪表已存哈希**全量比对**；
3. 全部一致且长表已有数据 → **跳过整段摄入**（这是真正的增量收益点）；
4. 任一变化 → **重算整张干净长表**并 upsert，再刷新哈希。

> **为什么不是逐文件增量**：白名单 / 名称映射是**全局过滤**，改一条登记可能影响所有行。
> 逐文件增量需要行级溯源，复杂度高且极易出错。文件级哈希门控已能拿到
> 「数据没变就跳过」的收益，其余情况用幂等 upsert 保证正确性。

**必须建索引**：日期列、店铺列（高频筛选维度）。

**建表必须是幂等的**：服务启动时自动 `CREATE TABLE IF NOT EXISTS`。

#### 2.2 聚合层（口径的**唯一事实来源**）

**核心是一个安全除法 + 一个派生指标函数 + 一个分组聚合函数**：

```python
# 安全除法：分母为 0 / null 时返回 None，绝不返回 Infinity（R-02）
def safe_div(a, b):
    return pl.when(b.is_not_null() & (b != 0)).then(a / b).otherwise(None)

# 派生指标：只做「本行的分子 / 本行的分母」
# 因为上游 aggregate 已先对分子分母各自求和，四层口径天然一致（R-01/R-03）
def compute_metrics(df):
    return df.with_columns(
        safe_div(col("buyers"), col("visitors")).alias("conversion_rate"),
        ...
    )

# 分组聚合：只累加可累加指标，比率交回 compute_metrics 重算（R-01/R-03）
def aggregate(df, keys):
    out = df.group_by(keys).agg(pl.col("amount").sum(), ...)
    return compute_metrics(out)
```

**铁律再述**：R-01（先求和再相除）、R-02（分母0 给 null）、R-03（比率不入长表）。

**产出两类 JSON**：
- **层级明细 JSON**：店铺 → SPU → 日期 → 指标。
  ⚠️ 同一 (店铺, SPU) 跨多日期时，**名称保留最新非空值**，否则后出现的空值会覆盖已得到的名称。
  ⚠️ 图表用的汇总 JSON **不要按店铺拆文件**（文件数随店铺线性膨胀），
  而是在 date 字段里带店铺前缀（如 `店铺A|2026-09-17`），前端按需过滤拆分。
- **汇总 JSON**：店铺×日期趋势（**必须排序**，否则折线会来回跳）、TOP 榜单、店铺汇总。

**Go/No-Go**：
- 写断言验证：2 天各自转化率 5% 和 50%，汇总必须是 `总客户数/总访客数`，
  **不是27.5%**。这条不过，后面全白搭。
- 长表**不含**任何比率字段（查列名确认）。

### 阶段 3 · API 层 + 静态托管

**做什么**：FastAPI 路由 + 单端口同时托管 API / SPA / 图片。

#### 3.1 ⚠️ R-15 再述：`index.html` 必须 no-store

SPA history 模式下 `index.html` 是「指向当前该用哪个 hash 资源」的入口。
让它被缓存会导致：改完前端重新 build，用户刷新仍拿到旧 `index.html` →
继续加载旧 hash 的 JS/CSS → **「代码改了、dist 也更新了、页面却完全没变化」**，
且极难自查（看 dist 是新的、看源码也是新的）。

- 带内容 hash 的 `/assets/*` → 可以长缓存。
- `index.html` → 显式 `no-store`。
- ⚠️ 这个修复**需要重启服务才生效**，写进文档。

#### 3.2 必须实现的能力

| 能力 | 要点 |
| --- | --- |
| 清单 | 各模块的店铺/日期区间/SPU 数 |
| 分页明细 | 支持日期区间参数；返回逐日数组，**缺失日指标为 `null`** |
| 汇总 | 图表用数据 |
| 单品分析 | 支持日期区间；趋势 / 工作日节假日 / 洞察 |
| 导出 | 全量数据导 xlsx（**不受前端分页影响**）；比率类总计 = 总量相除，**用字体色标记**（不用底色，避免压住数字） |
| 状态 / 刷新 | 上次批处理状态；手动重跑批处理并清缓存 |

#### 3.3 ⚠️ 性能铁律

- **静态目录用实时磁盘读取**（`StaticFiles`）：改前端只需重新 build，**无需重启服务**。
- **但改后端代码或重跑批处理必须重启**：否则旧进程返回旧字段，表现为「改了没生效」。
  这两条看似矛盾，**必须在文档里写清楚**，否则使用者必然踩坑。
- 数据加载用 `functools.lru_cache`；提供清缓存接口。

**Go/No-Go**：
- 只启动后端（`dist` 不存在）**不应崩溃**，只是不挂 SPA 路由。
- 直接访问前端深层路由（刷新）返回 `index.html`，不是 404。

### 阶段 4 · 前端基建（配置驱动 + 状态管理）

**这是全项目「可扩展性」的支点。**

#### 4.1 指标清单 = 唯一事实来源

**必须有一个 `metrics.ts`**，每条指标 spec 包含：
`key / 展示名 / 展示格式 / 分组 / 列宽 / 图表配色 / 是否默认勾选 / 聚合方式 / 对比字段名`。

**衍生能力（都从这份清单派生，不许手写第二遍）**：
- 指标卡（模块页+ 单品页）
- 表格列
- 趋势图 series
- 工作日/节假日对比项
- 指标配置面板的分组与条目
- 数值格式化分派

**聚合方式只有两种**：`{kind:"sum"}` 或 `{kind:"ratio", num, den}`。

**⚠️ 指标顺序按清单声明顺序，不按用户勾选顺序**：
否则用户随意勾选会让页面指标排列来回跳。

**⚠️ 新增一个指标要同步三处**：前端 metrics.ts 清单 + 后端输出模型字段 + 后端字段白名单。
少改一处，前端拿到 `undefined`。

#### 4.2 模块注册表 = 新增模块不写新页面

一个 `Record<moduleId, ModuleConfig>`：固定列（序号/商品信息）+ 尾列（操作列，`sticky:"right"`）。
新增模块在这里加一份即可，**不写新页面**。

#### 4.3 状态管理

- 模块数据 store：清单 / 汇总 / 筛选条件 / 排序 / 分页行 / 加载态 / 错误。
  ⚠️ **离开页面时 reset**，跨页不要依赖 store 派生 getter。
- 指标配置 store：**按模块 id 分开存 localStorage**，两个页面共用一份配置，天然同步。
  - localStorage key 带**结构版本**（如 `v1`），将来改结构时升 v2 并做迁移。
  - **隐私模式 / 存储被禁用时降级为默认值**，不阻断功能。

#### 4.4 格式化函数（缺失一律显示 `--`）

`number`（整数+千分位）/ `currency`（¥ + 两位小数）/ `percent`（小数 ×100 + %）/ `decimal`（两位小数）。

⚠️ **整数值格式化会取整，不要拿它格式化日均值**（15÷22=0.68 会显示成 1）。
日均走单独函数，最多保留两位小数。

**Go/No-Go**：
- 新增一个假指标，只改 `metrics.ts` 一处，看卡片 / 表格列 / 趋势图 / 配置面板是否**自动出现**。
  若需要改视图代码，说明配置驱动没做到位。

### 阶段 5 · 页面实现

#### 5.1 模块列表页

**两种形态，由所选日期区间自动切换，无需手动切模式**：

1. **单日模式**（区间起止同一天）：网格卡片，一商品一张卡，左图右指标（一指标一行）。
2. **区间模式**（起止不同天）：每个商品**独占一整行**，右侧「指标 × 日期」矩阵，
   列 = 区间内每一天，可横向滚动，所有商品的日期列对齐。

**顶部工具条保持一行**：区间选择（当月/上月/月份网格/全区间快捷）+ 搜索 + 数据区间状态
+ 上次更新时间 + 指标配置 + 手动刷新 + 导出。

**日期筛选逻辑单独成模块**（两个页面共用同一个组件，改一处即全模块生效）：

- **⚠️ R-14 再述**：「精确某年某月」必须直接传绝对年月，**不能用相对当月的 offset 换算**
  （offset 跨年时极易算错）。
- **月份清单由数据边界反推**，不写死「近 N 个月」：
  数据只有 2 个月时不该出现一堆空月份；数据跨 2 年时早期月份也要能选到。
- 月份面板的定位**按按钮实际位置像素级对齐**，不能沿用日历面板的 `left:0/right:0`
  （浮层挂在整行工具条下，`left:0` 对齐的是工具条左缘，不是按钮）。
- **判断「放不放得下」看面板左缘是否越出视口左缘**，不是看右侧空间
  （面板向左展开时右侧本就不需要空间）。

#### 5.2 单品分析页

指标卡 + 固定趋势图（含双轴组合，**两个都是百分比时左右轴共用同一量程**，刻度可直接比较）
+ 工作日 vs 节假日纵向条形图 + **月份对比**（默认收起）+ 自动生成的文字结论。

**日期默认值**：以数据最新日为终点往前 7 天（含最新日），数据不足一周时被最早日期截断。
手动改过区间后不再自动套回默认。

#### 5.3 ⚠️ R-05 再述：月份对比的「差额」按**单位**判定，不按算法

这是本项目最容易写错的地方之一：

| 指标 | 聚合方式 | 单位 | 差额写法 |
| --- | --- | --- | --- |
| 成交转化率 | ratio | `percent` | **百分点 pt**：`1.92% → 1.56%` = `−0.35pt` |
| 客单价 | ratio | `currency` | **金额**：`¥489.32 → ¥510.90` = `+¥21.58` |
| 商品访客数 | sum | `number` | **数值**：`−1,067` |
| ROI | ratio | `decimal` | **数值**：`−0.38` |

**客单价是 ratio 聚合但单位是金额**——若按聚合方式判定，会得出 `+2158.00pt` 这种离谱值。
**判据必须是展示格式（单位），不是聚合算法。** 字段命名也必须体现这一点
（叫 `isPercent` 而不是 `isRatio`，因为 `ratio ≠ 百分比`）。

**「差额」与「变化」两列并存**：
- 差额 = 绝对差（转化率少了 0.35 个**百分点**）
- 变化 = 相对变化率 `(新−旧)/|旧|`（同一件事 **−18.5%**）

两者回答的是**不同问题**，不冲突。全类型都给变化率，分母为 0 给 `--`。

**颜色只按数值方向**（**绿涨红跌**，国内习惯），**不做业务好坏判断**：
推广花费下降业务上是好事，仍标红。

**⚠️ 变化列不要迷你条形**：条形需要「全表最大变化率」做归一化基准，
基准一变所有条形长度都跟着变，读者要跨行比较才能读出大小；
且比率类的百分点差本就不可横向比较（0.5pt 可能是暴涨也可能是暴跌），
画成条会给出错误的可比性暗示。

#### 5.4 展开行内的时间轴大图（若做此功能）

⚠️ **四条硬约束**（每条都对应一个真实 bug）：

- **R-09 再述**：必须 1:1 渲染。`viewBox` 写死而容器更宽时，浏览器会按比例拉伸
  （实测曾达 `scaleX=1.979`，内容巨大违和）。此时调小字号只是治标。
  做法：`ResizeObserver` 测容器真实宽 → 动态生成 `viewBox`，使内部坐标单位 == CSS 像素。
- **宽度按数据点数反推**，而非恒等于容器宽
  （`W = PAD_X*2 + (n-1)*SEG`，再夹在容器上限内）：
  点少则窄、点多线性变宽、超出则压缩并横向滚动。靠左对齐不居中。
- **R-10 再述**：`v-for` 内的 DOM 引用必须用**函数式 ref**（字符串 ref 会聚成数组）。
- **R-11 再述**：SVG `marker`/`clipPath` 的 `id` **按行加后缀**。

⚠️ **若允许多行同时展开**，还有两处隐藏的单值假设必须一并改造：
- 展开状态从单值 `Ref<string|null>` 改为 `Set<string>`（用**新 Set 替换**以触发变更检测，
  原地 `add`/`delete` 不触发）；
- 几何计算从单值 `computed` 改为**按 key 取的普通函数**（每行要各用自己的几何，
  单值 computed 无法表达）；
- 观察容器从单元素改为 `Set`，宽度取**最大值**；
  ⚠️ 函数式 ref **解绑时的 `null` 不能清空集合**（否则会把其它已展开行踢出观察范围）。

#### 5.5 通用 UI 约定

- **design token**：颜色 / 圆角全部走 `:root` CSS 变量。
  ⚠️ 语义色要区分：「涨」的绿与「操作成功」的绿**不是同一个色**
  （后者偏青绿，同屏出现两种绿像两套语义）。抽token 时一次抽对，别留散落硬编码。
- **浮层互斥**：同页多个浮层用模块级 ref + 实例唯一 id，全局只允许一个展开。
- **可点击提示**：仅靠 `:hover` 解决不了「压根没看到」，必须配**不依赖悬停的静态标识**
  （如「点击展开」胶囊标签）。收起态与展开态要有视觉区分
  （展开后继续用「可展开」的红色三角会让人误以为还有别的可展开内容）。
- **一次性动效只播一次**（`sessionStorage` 记录）：常驻循环动画是页面噪音，反而让人不再注意。
- **动效须有 `prefers-reduced-motion` 降级**。
- **对 `transform` 做动画的元素**：若已有 `rotate`，动画必须用独立的 `translate` 属性，
  否则动画会覆盖旋转；`transform`（旋转）与 `fill`（变色）也要分写在两条 `transition` 里。
- **给关键区块加 `data-testid`**（命名：页面前缀 + `-` + 语义），并维护一份「路由 → 组件 → 关键元素」地图。
  这是降低后续改动成本的低成本手段。

**Go/No-Go**：
- 改一个 `.vue` 里的样式，重新 build，**只刷新浏览器**（不重启服务）即可看到效果。
- 单日模式与区间模式都能正常渲染，切换无需手动干预。

#### 6.2 必须交付的可执行验证（**不是「跑通了」**）

见 `03-验收清单.md`。核心三条：

1. **回归断言脚本**（`npm run verify`）：验最容易写错的口径逻辑。
   - 纯逻辑部分（天数计算 /闰年 / 跨月 / 对齐方向）与接口一致性部分分开两个脚本。
   - 用 `esbuild --bundle` 就地转译 `.ts` 后由 node 执行（不必额外装 tsx），产物落`node_modules/.cache/`。
   - ⚠️ **断言失败时先怀疑测试本身**——历史多次 FAIL 都是期望值写错
     （浮点未考虑四舍五入、符号逻辑写反）。浮点用容差，期望是舍入结果时
     容差按舍入粒度给（如 0.005）而非 `1e-9`。
2. **真实浏览器实测**（UI 改动交付前必做）：
   ⚠️ **在构建产物里 grep 字符串只能证明「构建通过」，不能证明「浏览器里生效」。**
   用系统浏览器的 headless 模式 + 调试协议，读 `getComputedStyle` /
   `getBoundingClientRect` / 截图人工核对。
   - ⚠️ headless 默认视口很小（会因换行得到荒谬尺寸），必须**先设桌面尺寸再重新加载**。
   - ⚠️ 测**动画**要抓过程值（挂载瞬间连读多次），不能只看终态——
     一次性动效在「固定等若干秒再读样式」时必然测到 `none`。
   - ⚠️ 测**hover** 必须用真实鼠标事件（不能合成 `dispatchEvent`），且**挑未展开的行**做样本
     （已展开的行本来就是目标色，测它会得出「没生效」的假结论）。
   - ⚠️ 「看起来没变化」先区分两种情况：①真没生效②生效但幅度不可见。别把②当①重调。
3. **文档一致性检查**：文档里的每条命令都应实际可执行；
   「被忽略的文件清单」要与`.gitignore` 逐条对应。
   ⚠️ 文档会漂移（实测发现部署指南里「某目录默认提交」的说法，
   早已被 `.gitignore` 排除且仓库中 0 个跟踪文件）。**每改动配置就同步文档。**

#### 6.3 文档交付

- **使用说明**：面向运营/数据同学，含架构表、数据流图、两种页面形态说明、接口速查、
  本地启动（两种方式）、排障表、**维护注意事项**（改什么需要 build / 需要重启）。
- **变更记录**：**每条只记「改了什么 + 为什么 + 涉及文件」**，
  调试流水、实测数据不进这一节（放工作日志）。
  ⚠️ 变更记录会越来越长，**要定期压缩**：保留「改了什么/为什么」，
  删调试过程。流水账式的变更记录等于没有变更记录。
- **代码注释规范**（写进文档并严格执行）：
  1. 注释用**中文**，标识符用**英文**；
  2. 所有类 / 公开函数必须有文档注释：功能 / 每个参数（类型、含义、是否可选、默认值）/
     返回值 / 可能抛出的异常及触发条件 / **至少一个调用示例**；
  3. 复杂逻辑、边界处理、异常分支必须有行内注释，解释「**为什么这么做**」和业务含义；
  4. 关键变量/常量/配置项注释用途；
  5. **禁止废话注释**（「i++ 是自增」）；
  6. **改代码必须同步更新注释**；
  7. **输出完整代码，不许省略**（禁止 `// 其余同上` 这类占位）。

## 九、开始之前：三条最重要的提醒

1. **口径纪律 > 功能数量。** 少做一个功能没关系，口径漂移是**数据事故**——
   一旦「单日对、汇总错」，使用者会怀疑整个平台的数据可信度。
2. **同一份数据只允许一个事实来源。** 表头显示的天数、实际取数用的天数、
   脚注里举例用的天数，必须来自同一个 computed。历史上「已按 30 天截取、表头写 31 天」
   就是两个来源导致的。
3. **验证要可执行，不是「跑通了」。** grep 构建产物只能证明构建成功，
   只有真实浏览器读到计算样式才能证明页面生效。
