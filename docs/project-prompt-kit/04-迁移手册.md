# 迁移与部署手册

> 配套 `00-主提示词.md` 第六阶段。覆盖：兼容性、部署链路、换数据库、跨平台、常见故障。

## 一、设计目标：三个「换」不用改代码

| 换什么 | 靠什么做到 |
| --- | --- |
| **换机器 / 换盘符 / 改项目名** | 所有路径由 `__file__` 推导；虚拟环境在项目根；脚本不烧死路径 |
| **换数据目录** | 环境变量 `JD_DATA_DIR` / `POP_SOURCE_DIR` |
| **换数据库** | Source 协议隔离 + 预留数据库源骨架 |

⚠️ **反面做法（明确禁止）**：
- 在批处理/启动脚本里写绝对路径 `E:\xxx\...`；
- 在计划任务里烧进解释器完整路径；
- 用`config.yml` 存机器相关配置（它应是空 `{}`）。

## 二、环境变量全覆盖

```python
# config.py —— 只放常量，全部支持环境变量覆盖
BACKEND_DIR = Path(__file__).resolve().parent.parent
DATA_DIR    = Path(os.getenv("JD_DATA_DIR",   BACKEND_DIR / "app" / "data"))
DB_PATH     = Path(os.getenv("JD_DB_PATH",    DATA_DIR / "app.db"))
SOURCE_DIR  = Path(os.getenv("POP_SOURCE_DIR", BACKEND_DIR.parent / "<业务数据目录>"))
PG_DSN      = os.getenv("PG_DSN", "")            # 留空 = 跳过数据库源
RETRY_ENABLED = os.getenv("BATCH_RETRY_ENABLED", "false").lower() == "true"
```

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `JD_DATA_DIR` | 批处理产出目录（JSON/图片/DB） | `backend/app/data` |
| `JD_DB_PATH` | SQLite 文件位置 | `{DATA_DIR}/app.db` |
| `POP_SOURCE_DIR` | 业务数据源根目录 | 项目下`<业务数据目录>` |
| `PG_DSN` | 数据库连接串；**留空则跳过数据库源** | 空 |
| `BATCH_RETRY_ENABLED` | 批处理失败是否重试 | `false` |
| `BATCH_RETRY_MAX_ATTEMPTS` | 重试次数（含首次） | `3` |
| `BATCH_RETRY_BASE_DELAY` | 指数退避基数秒 | `2.0` |

**零配置原则**：所有配置项都有默认值，**新机器不需要写任何配置文件即可跑通**
（示例：`config.yml` 是空 `{}`，不需要 `.env`）。

### 2.1 ⚠️ 重试为什么默认关闭

上游数据出错时重试多半也是同样的错，**不如让失败显式暴露由人排查**。
需要无人值守时再打开。

## 三、异地克隆部署链路

### 3.1 为什么 clone 下来是「半成品」

仓库**故意没存**四类内容：

| 缺什么 | 为什么 | 怎么补 |
| --- | --- | --- |
| Python 虚拟环境 | 含绝对路径，不可跨机器拷贝 | `pip install -r requirements.txt` |
| 前端 `node_modules` | 几百 MB | `npm install`（有 lock 文件） |
| 前端 `dist` | 编译成品 | `npm run build` |
| 运行时数据（`data/`） | 生成物| `python -m backend.jobs.run_batch` |
| **业务数据目录** | 体积大 + 业务敏感 | `python scripts/setup_sample.py` 铺样例 |

### 3.2 五步链路

```bash
# 0) 前置：Python 3.12+ / Node.js 22+ / Git

# 1) 克隆
git clone <repo> && cd <repo>

# 2) 后端依赖（虚拟环境建在项目根）
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements.txt

# 3) 前端依赖 + 构建（⚠️ 最容易漏）
cd frontend && npm install && npm run build && cd ..

# 4) 铺样例数据（业务数据不入库）
python scripts/setup_sample.py

# 5) 生成运行时数据
python -m backend.jobs.run_batch

# 6) 启动
scripts\start_uvicorn.bat          # Windows（自动推导根目录、检查 venv）
# 或
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

### 3.3 ⚠️ 两个「致命坑」

|坑 | 症状 | 原因 |
| --- | --- | --- |
| **不build** | 打开 8000 端口空白 / 404，只有 `/docs` 能用 | 服务检测不到 `dist` 就不挂 SPA 路由（**这是有意的**——只跑 API 调试不该崩） |
| **不跑 run_batch** | 服务能起，页面骨架在但**数据全空**，图片裂 | 所有数据接口靠 `data/` 里的 JSON 和图片 |

### 3.4 依赖关系图

```
clone
  ├─ 后端：venv + pip install      ┐
  ├─ 前端：npm install + build     ├─ 三者互不依赖，可并行
  └─ setup_sample + run_batch      ┘   （需后端依赖 + 数据源）
                ↓
                启动服务（需 dist✅ + data ✅ + .venv ✅）
```

**最短路径**：后端依赖 → build 前端 → 铺样例 → run_batch → 启动。

### 3.5 验证成功（三处都对）

1. `http://localhost:8000` → 看到数据页面；
2. `http://localhost:8000/docs` → API 文档在；
3. `status.json` 里 `"success": true`。

## 四、两种启动方式

### 4.1 托盘启动器（推荐给运营）

**双击 `scripts/启动服务.pyw`**：全程无黑框，系统托盘出图标，右键菜单「打开面板 / 退出」。

实现要点（都是踩过坑的）：

- **纯 stdlib引导器 `.pyw`** 拉起托盘脚本。
  ⚠️ **不要用 `.vbs`**——WScript 按ANSI 读编码，中文注释会吞行导致解析失败。
- **主线程跑托盘 + 子线程跑 uvicorn，同一个进程**。
  ⚠️ **不要用 subprocess 调 CLI，也不要 `reload`**——会产生孤儿进程与端口残留。
- **单实例锁**：日志目录下的锁文件用 `O_EXCL` 原子创建 + PID 存活探测。
  ⚠️ 旧版只用 `os.kill(pid,0)` 探测，**Windows 上会把活实例误判为已死** →
  第二个实例照样起 uvicorn → 绑8000 失败，留下**无服务的僵尸托盘**。
  修复：加**端口探测**（探 `127.0.0.1:8000`），已监听则只开浏览器后退出，不碰锁。
- **进程枚举必须限定 `python.exe` / `pythonw.exe`**：
  否则启动它的外壳命令行同样含脚本名，会「把自己当另一个实例」自我拦截。
- ⚠️ **`pythonw` 无 stdout**，所有输出必须落盘，否则出错**静默消失**。
- 退出时**先隐藏图标再停服务**，避免 Win11 幽灵图标。

### 4.2 命令行（调试 / 服务器）

```bash
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

### 4.3 ⚠️ 端口占用

```powershell
netstat -ano | findstr :8000        # 拿 PID
Stop-Process -Id <PID> -Force
```

## 五、计划任务 / 定时刷新

### 5.1 ⚠️ 刷新要「服务无关」

**旧方案的问题**：`POST /api/refresh` 强依赖服务在线，服务没起则整段失败——
但「每日自动刷新」本该在服务没起时也能把数据准备好。

**正确做法**：
1. **直接跑 `run_batch`**（不依赖服务）；
2. 跑成功后「尽力」POST 刷新接口，**仅用于让正在运行的服务清缓存**（失败无妨）。

### 5.2 ⚠️ 迁移兼容要点

| 要点 | 做法 |
| --- | --- |
| 项目根 | 由 `__file__` 推导 |
| 解释器路径 | **运行期按候选列表解析**（不烧进计划任务） |
| 刷新地址 | 走环境变量 |
| 换机/换盘符/迁 Docker | **无需改代码** |
| 任务间依赖 | 用「前置任务 + 失败不阻断」策略 |
| `.ps1` / `.bat` 内容 | ⚠️ **必须纯 ASCII**（PS 5.1 / cmd 按 GBK 读 UTF-8，中文注释会吞行） |

建议注册两个任务：
- **每日定时刷新**（如 03:00）——数据常新；
- **登录自启** —— 免手动启动。

⚠️ **注册计划任务需要管理员权限**。提供一键注册脚本，内部做自提升。

## 六、换数据库：SQLite → PostgreSQL

### 6.1 为什么预留骨架

SQLite 适合「单机内网、双击即用」；
但若数据量涨到百万行级，或需要多用户并发写，就得换。

**因为持久层已被Source 协议隔离**，换库只影响三处：

```
① 实现同一个 Source 协议从 PG 读（新建 db_pg_source.py）
② 改config.py 的连接配置
③ 建表 SQL 方言适配（占位符 ? → %s，自增语法）
```

**下游全不动**：聚合层、API、前端完全无感。

### 6.2 ⚠️ 迁移时的三个陷阱

| 陷阱 | 说明 |
| --- | --- |
| **比率不能入库** | 这条铁律在 PG 上同样成立。若之前已在 SQLite 存了比率，**迁移时要先清掉重算** |
| **增量策略要重新设计** | 文件哈希方案对数据库源不适用——DB 源应改用`updated_at` 时间戳或变更捕获 |
| **唯一键约束要对齐** | `INSERT OR REPLACE` 是 SQLite 语法，PG 要用 `INSERT ... ON CONFLICT DO UPDATE` |

### 6.3 迁 Docker 的额外注意

- 业务数据目录**挂 volume**，不要打进镜像；
- 环境变量通过 compose 传入，**不要 `ENV` 硬编码**；
- `dist` 在镜像构建时生成；`data/` 建议用 volume + 启动时跑批处理；
- 保留「先跑批处理再启服务」的顺序（或用 entrypoint 串起来）。

## 七、跨平台注意事项

| 事项 | 说明 |
| --- | --- |
| **托盘启动器** | 纯 Windows（`pystray` 依赖系统托盘）；Linux/Mac 用命令行或 `systemd` / `launchd` |
| **脚本编码** | ⚠️ `.ps1` / `.bat` / `.vbs` **必须纯 ASCII**；`.py` / `.pyw` 中文注释安全 |
| **PowerShell 5.1** | 不用 `*>` 重定向（写 UTF-16）；用 `Out-File -Encoding utf8`或 `[IO.File]::WriteAllText(..., UTF8)` |
| | 不用 `&&` / `??` / `?:`（PS7 才支持） |
| **shell 调用限制** | 某些环境策略禁止 shell 调 shell（如 cmd 调 powershell） |
| **删文件** | 若被安全策略拦截，用 `.NET` 的 `File.Delete()` / `Directory.Delete()` |
| **路径** | 代码内一律用 `Path`，不要手拼 `\` 或 `/` |

## 八、常见故障排查表

| 症状 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 8000 打开空白 / 404 | 未 `npm run build` | build 后刷新 |
| 页面骨架在但数据全空 | 未跑 `run_batch` | 跑批处理 |
| 图片全裂 | 同上（图片在 data 目录） | 跑批处理 |
| **改了前端没生效** | 浏览器缓存了 `index.html` | 先 Ctrl+F5；后端 `no-store` 修复**需重启服务** |
| **改了后端没生效** | 旧进程内存里是旧代码 | **重启服务** |
| 改了数据源但页面没变 | 没重跑批处理 **+** 没重启 | 两者都要 |
| **新店铺/新商品没出现** | ⚠️ **白名单闸门**——未在登记表中登记 | 检查登记表（第一现场） |
| 比率全是 0 | 隐藏分子没参与累加（R-04） | 检查累加字段集合 |
| 汇总比率与单日对不上 | 比率被算在明细行（R-01/R-03） | 比率移出长表 |
| 显示 `Infinity` / 图表崩 | 分母 0 未兜底（R-02） | 用 `safe_div` |
| 日期差一天 | 用了 `toISOString()`（R-13） | 改本地时间 + 手动补零 |
| CSV 读取报 `CalamineError` | Excel 打开产生的 `~$*.xlsx` 锁文件 | 扫描时过滤 `~$*` |
| 缩略图不生成 | Pillow 缺 AVIF 插件 | 装 `pillow-avif-plugin` |
| 装依赖卡在 Pillow | 国内镜像缺 AVIF 轮子 | 换阿里云源：`-i https://mirrors.aliyun.com/pypi/simple/` |
| 单实例失效 / 僵尸托盘 | 只用 PID 探测（Windows 误判） | 加端口探测 |
| 计划任务里中文注释导致解析失败 | `.ps1`/`.bat` 非纯 ASCII | 改纯 ASCII |

## 九、数据安全与可重建性

**核心原则：任何运行期产物都能从源文件重建，删了不心疼。**

| 内容 | 是否入库 | 怎么重建 |
| --- | --- | --- |
| 数据库文件 | ❌ | 删了重跑 `run_batch` |
| JSON 产出 | ❌ | 同上 |
| 图片 / 缩略图 | ❌ | 同上（缩略图幂等重算） |
| 业务数据源 | ❌ | 需外部提供 |
| **样例数据** | ✅ | 供新机器/CI 起项目 |
| 代码 / 配置 / 文档 | ✅ | — |

**配套脚本**：把样例数据复制到真实数据目录，让新机器/CI 能起项目。

⚠️ **删库的正确姿势**：直接删文件即可，不需要额外迁移脚本。
建表语句是幂等的（`CREATE TABLE IF NOT EXISTS`），服务启动时自动建。

## 十、给agent 的迁移自检表

- [ ] 项目改名 / 移动位置后，虚拟环境与启动脚本仍可用
- [ ] 环境变量全部覆盖路径，无硬编码绝对路径
- [ ] `config.yml` 是空 `{}`（或不存在），新机器零配置可跑
- [ ] 干净克隆 → 按文档五步→ 三处验证全过
- [ ] 数据库文件不在 git 里，删了能重建
- [ ] 批处理**重复跑两次结果一致**（幂等）
- [ ] 未跑 build 时服务**不崩溃**（只是不挂 SPA）
- [ ] 托盘启动器单实例有效（连开两次只有一个服务）
- [ ] 刷新脚本不依赖服务在线
- [ ] `.ps1` / `.bat` 内容纯ASCII（`file` 命令或编辑器确认）
- [ ] 换数据库的路径已在注释里写明（哪三个文件要改）
