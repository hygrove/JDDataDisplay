# JDDataDisplay 项目全景与运行机制

> 目标：让你不看代码也能在脑子里跑通「数据怎么来、前后端怎么协作、页面怎么动」。
> 读完后建议配合源码（`backend/app/api.py`、`frontend/src/**`）对照看，记忆更牢。

---

## 0. 一句话定义

这是一个**电商数据可视化平台**：每天把散落的 Excel/CSV 源表，批处理成结构化的 JSON + 缩略图，再由一个 FastAPI 单端口**同时**提供「数据接口 + 前端页面 + 图片」，浏览器里的 Vue3 单页应用负责把数据画成表格、指标卡和趋势图。

核心心智模型只有一条链：

```
Excel/CSV(ResourceData) ──批处理──▶ data/(JSON+图片) ──FastAPI──▶ 浏览器 Vue 渲染
                                          ▲                         │
                                          └──── GET /api(JSON) ──────┘
```

---

## 1. 技术栈速查

| 层 | 技术 | 职责 |
|----|------|------|
| 数据生产 | Python + openpyxl/Calamine + **polars** + SQLite | 清洗源表、聚合、产出 JSON 与图片 |
| 服务层 | **FastAPI** + uvicorn | 单端口托管 API + 静态资源 + SPA |
| 展示层 | **Vue3 + Vite + TypeScript + Pinia + Vue Router** | SPA 页面、状态管理、路由 |
| 调度 | Windows 计划任务（SYSTEM，每天 20:15） | 无人值守跑批处理 |
| 产物存储 | 本地文件系统（`backend/app/data/`）+ SQLite | 不进 git，每次批处理重建 |

⚠️ 关键点：**没有 pandas**，也没有独立的前端 dev 后端——开发与生产共用同一套 FastAPI，只是开发时用 Vite 代理转发。

## 2. 三个角色详解

### 2.1 数据生产：`backend/jobs/`（Python 批处理）

这是「数据从哪来」的答案。入口是 `run_batch.run_once()`，每天被计划任务调用一次：

1. **摄入 `db.ingest_excel_to_db`**：把 Excel/CSV 清洗成一张**长表** `daily_detail`，落进 SQLite（`data/app.db`）。用「全量内容 sha256 字典」做门控——只要源文件内容变了就整表重算。
2. **管线 `pipeline.run_all`**：从 SQLite 读干净长表，用 **polars** 拼装成每个模块的层级 JSON（`modules/{id}.json`）、汇总（`{id}.summary.json`），最后写 `manifest.json`（前端首屏第一跳）。同时把 SPU 图片同步到 `data/images/` 并生成 96/120/180 多尺寸缩略图（AVIF+WebP）。
3. **状态 `status.json`**：成功/失败、耗时、模块数，供前端展示「上次更新」。退出码 0/1 供调度判断。

产物全在 `backend/app/data/`（被 `.gitignore` 忽略，不进版本库）。

### 2.2 服务层：`backend/app/`（FastAPI 单端口 8000）

`main.py` 是装配核心，挂载顺序是有硬约束的：

```
include_router(api_router)        # /api 业务接口
mount("/images")                  # SPU 原图
mount("/thumbs")                  # 缩略图
mount("/assets")                  # 前端构建产物里的静态资源
GET /{full_path:path}  SPA 回退    # 兜底返回 index.html
```

⚠️ **挂载顺序铁律**：SPA 回退路由会吞掉一切未匹配的 GET。所以 `/images` `/thumbs` `/assets` 必须写在它**之前**，否则图片请求会被回退成 `index.html`（表现为「页面能开、图片全 404」）。

启动时 `ensure_schema()` 幂等建表（保证服务起来就有表）。`startup` 只建表，真正的摄入由批处理完成。

`api.py` 提供接口（全部前缀 `/api`）：
- `GET /manifest` —— 模块清单（首屏第一个请求）
- `GET /module/{id}/rows` —— 分页明细（过滤/排序/分页，绝不整模块推给前端）
- `GET /module/{id}/summary` —— 图表汇总
- `GET /module/{id}/spu/{spu}/analysis` —— 单品分析（工作日/节假日对比 + 文案）
- `POST /module/{id}/export` —— 导出 xlsx
- `GET /status` —— 批处理状态
- `POST /refresh` —— 手动重跑批处理（同步，完成后清缓存）

### 2.3 展示层：`frontend/`（Vue3 SPA）

`src/main.ts` 一行完成装配：

```ts
createApp(App).use(createPinia()).use(router).mount("#app");
```

⚠️ **顺序铁律**：`createPinia()` 必须在 `router` 之前。因为路由守卫 `beforeEach` 里会调 `useUiStore()`，若 Pinia 还没装好，首次导航就报「no active Pinia」。

## 3. 数据链路端到端（核心，务必吃透）

把一次「打开模块页看到数据」拆开看：

1. **落盘**：批处理把 `ResourceData` 的 Excel → SQLite 长表 → 层级 JSON（`shop → spu → date → metrics`）+ 缩略图，全部放进 `data/`。
2. **首屏**：浏览器加载 `index.html` → Vue 启动 → `App.vue` 的 `onMounted` 调 `fetchManifest()`（第一个 API 请求）→ 拿到清单 → 自动跳到第一个模块 `/module/pop_spu_detail`。
3. **拉数据**：`ModuleView` 调 `store.init(moduleId)` → 并行 `fetchSummary()`（图表）+ `fetchRows()`（首屏 300 行）。`fetchRows` 带的参数就是前端筛选态（shop/start/end/keyword/sort/page）。
4. **后端处理**：`api.py` 的 `flatten_module` 把层级 JSON 拍平成「一行=一个 SPU 一天」的列表（带缓存 + RLock 双重检查加锁）；`_build_rows` 按店铺/日期/关键词过滤、按 `(shop,spu)` 聚合、排序分页，返回 `PagedRows`（total + 当页 rows）。
5. **渲染**：Pinia `module` store 收下 rows → 组件用 `modules/index.ts` 的配置 + `metrics.ts` 的指标清单把数据画成表格列、指标卡。
6. **无限滚动**：页面触底 → `store.loadMore()` 取下一页 `concat` 上去，直到 `hasMore` 为假。

🔑 **前后端字段契约**：后端 `api.py` 的 `METRIC_KEYS`、后端 `models.MetricRecord` 字段、前端 `metrics.ts` 的 `METRICS` 三者必须对齐。新增指标要改这三处，否则前端拿到 `undefined`。

## 4. 前后端协作：两套部署形态

| 形态 | 前端怎么跑 | 后端怎么跑 | `/api` 怎么通 |
|------|-----------|-----------|---------------|
| **开发** | `npm run dev`（Vite :5173） | uvicorn :8000 | Vite **proxy** 把 `/api`、`/images`、`/thumbs` 转发到 `127.0.0.1:8000` |
| **生产** | `npm run build` → `dist/` | 同进程托管 `dist/` | 同源 8000，无代理 |

⚠️ **dev 的两个坑（已在 `vite.config.ts` 注释里钉死）**：
- 代理目标必须写 `127.0.0.1` 而不是 `localhost`：`dns.lookup('localhost')` 返回 `[::1, 127.0.0.1]`，Node20+ 不回落，而 uvicorn 只听 IPv4 → 整站 502（但 `curl localhost:8000` 正常，极具迷惑性）。
- 前端可见的静态前缀 `/api`、`/images`、`/thumbs` 必须在 proxy 里**列全**，漏 `/thumbs` 会让 dev 下图片全裂（生产正常）。

### 路由转发（后端侧）

- Vue Router 用 **history 模式**（URL 不带 `#`）。直接访问 `/module/xxx` 时后端没有物理文件，靠 `main.py` 的 SPA 回退返回 `index.html`，再由前端路由接管——否则刷新页面会 404。
- 回退的 `index.html` 强制 `no-store`：因为带 hash 的 `/assets/*.js` 是内容寻址、可长缓存，但 `index.html` 是入口，缓存它会导致「改了前端却看不到变化」。

## 5. Pinia 三仓库：职责与协作

项目刻意把状态拆成三个 store，互不污染：

| Store | 文件 | 管什么 | 生命周期 |
|-------|------|--------|----------|
| `useModuleStore` | `stores/module.ts` | 模块数据：manifest、summary、rows、筛选态（shop/起止/关键词/排序）、分页 | 切模块 `reset()`，但**保留** manifest（换模块复用，不重复请求） |
| `useUiStore` | `stores/ui.ts` | 仅「路由级全屏加载遮罩」这个跨页瞬时态 | 全局单例 |
| `useMetricsStore` | `stores/metrics.ts` | 「当前模块勾选了哪些指标」，按 moduleId 存 **localStorage** | 全局单例，模块页与分析页共用 → 天然同步 |

**协作关系**：
- `App.vue` 用 `module` store 拉 manifest 并渲染左侧导航；用 `ui` store 控制遮罩。
- `ModuleView` 用 `module` store 拉数据；用 `metrics` store 决定表格/卡片显示哪些列。
- `SpuAnalysisView`（单品分析页）**不**调 `module.init()`，所以 `App.vue` 的店铺列表改为「按路由上的 `moduleId` 查 manifest」而非读 store——这是特意规避的分析页态丢失坑。
- `metrics` store 用 `normalize()` 过滤掉已下线的指标 key 并按清单排序，保证旧存档不报错；写入持久化走唯一 `persist()` 路径。

💡 **记忆口诀**：业务数据进 `module`，跨页瞬时 UI 进 `ui`，用户偏好（勾选）进 `metrics` + localStorage。

## 6. 路由与加载遮罩

`router.ts` 只有三条路由：`/`（空白，自动跳转）、`/module/:moduleId`、`/module/:moduleId/spu/:spu`。视图全部**懒加载**（尤其单品分析页含 echarts 大 chunk）。

`beforeEach` 守卫：只有跳到 `spu-analysis` 时才 `ui.setNavigating(true)` 点亮全屏遮罩——因为大 chunk 下载期间目标组件还没挂载、它自己的遮罩不会出现，用户会以为「点了没反应」。组件 `onMounted` 后再 `setNavigating(false)` 复位，把遮罩交棒给页面自身遮罩。`onError` 兜底复位，防遮罩永久卡死。

⚠️ `useUiStore()` 必须在导航**运行时**调用（Pinia 已装好），不能放模块顶层。

## 7. 指标的唯一事实来源（前后端对齐契约）

前端 `metrics.ts` 的 `METRICS` 是整个前端「展示哪些指标、怎么聚合、怎么格式化」的**唯一事实来源**：
- 模块页的指标卡、表格列，单品分析页的指标卡、趋势图、工作日/节假日对比，全部由它派生（以前手写 4 份，改一处要改 4 处）。
- 每个指标有 `agg` 口径：`sum` 直接求和 vs `ratio`（先分别累加分子分母再相除）。⚠️ 比率类（转化率/客单价/点击率/ROI/推广占比）**必须**走 `ratio`，否则多日汇总会得到「每天百分比相加」的错误结果。
- 后端 `api.py` 的 `METRIC_KEYS` 也复制了一份 key 全集，作为排序白名单（避免把任意属性名拼进 `getattr`）。

## 8. 后端 API 缓存与刷新机制

`api.py` 用三个模块级字典 `_module_cache / _summary_cache / _flat_cache` + 一把 **RLock**（可重入，因为 `flatten_module` 内会再调 `load_module`，普通锁会死锁）做「双重检查加锁」懒加载：无锁快读 → 未命中才加锁 → 锁内再查一次。扁平行（`flatten_module`）是性能关键——单品分析和导出都在它之上按需聚合，所以切区间/切 SPU 是毫秒级，真正的重算只在 `/refresh` 时。

`POST /refresh`：同步跑完整批处理 → **必须** `clear_caches()`，否则接口继续返回旧数据（表现为「刷新了但页面没变」）。

## 9. 定时调度

Windows 计划任务 `JDViz_DailyRefresh`：**每天 20:15，SYSTEM 身份**，走 `refresh_daily.ps1` → `refresh_data.py` → 在自己进程内调 `run_batch.run_once()`。另有 `JDViz_UvicornAutoStart`（登录时启动托盘服务）。

⚠️ 重要认知：20:15 的任务跑的是**工作区里那份代码**，不是某个 git 提交。没提交的半成品会被当晚任务直接吃到；改后端后要生效要么重启托盘服务，要么等 20:15 新进程（新进程天然拿新代码）。

## 10. 关键不变式与排坑清单（保命用）

- **长表只增不减**：`daily_detail` 只有 `INSERT OR REPLACE`，全项目无 `DELETE`。把源表移走不会清对应行 → 冻结成「僵尸行」（仍聚合、不更新、不报错）。凡「移走源表」的功能，必须先证明被移走的 key 在别处有来源。
- **门控 = 全量内容 sha256 字典相等**，不含 mtime/大小；增/删/改名/改内容一律整表重算。
- **明细 vs 推广过滤条件不一致**：明细要 spu 非空 + 非合计 + 日期正则；推广只要求 spu 非空 + 非合计（无日期正则）。key 提取必须复用各自规则，别统一。
- **改完 `.vue`/`.ts` 必须 `npm run build`**（FastAPI 托管 `dist/`）；grep dist 只证明构建通过、不证明浏览器生效。
- **判定与渲染分离**：判定逻辑进 `src/modules/*.ts` 纯函数（`roi=null 被当 0 排序` 这类错页面看正常，只有断言能抓）。

## 11. 如何新增一个模块（扩展点）

配置驱动，基本不写新页面：
1. 实现 `Source` 协议（`sources/base.py`），在 `pipeline.default_registry()` 加一条 `ModuleSpec`（module_id/title/sources）。
2. 可选：在 `transforms.py` 为该模块定制转换。
3. 前端 `modules/index.ts` 的 `MODULE_CONFIGS` 加一份（leadColumns/tailColumns）。
4. 同步指标契约：后端 `models.MetricRecord` + `api.METRIC_KEYS` + 前端 `metrics.METRICS`。
5. 跑一次批处理 → 前端自动出现新模块入口。

## 12. 推荐上手路线图（按这个顺序读，最快建立全局观）

1. **先读本文 + 上面的架构图**（已在脑子里建立骨架）。
2. **后端数据生产**：`backend/jobs/run_batch.py` → `db.py`（摄入）→ `pipeline.py`（产出）。看数据怎么从 Excel 变成 JSON。
3. **后端服务**：`backend/app/main.py`（挂载顺序）→ `backend/app/api.py`（接口与缓存）。这是前后端的分界。
4. **前端入口**：`frontend/src/main.ts` → `router.ts` → `App.vue`。看页面怎么起来、怎么跳。
5. **前端状态**：`stores/module.ts`（数据中枢）→ `stores/metrics.ts`（勾选偏好）→ `stores/ui.ts`（遮罩）。
6. **前端配置驱动**：`modules/index.ts`（列/卡片生成）+ `metrics.ts`（指标唯一事实来源）。
7. **对照契约**：同时打开后端 `METRIC_KEYS` 与前端 `METRICS`，理解前后端字段如何对齐。
8. **动手验证**：改一个指标的中文标题，跑 `npm run build`，看前端是否变——验证你真的理解了「唯一事实来源」这条链。
